# Session Manager v0.4.0-dev Devlog

> Status: Development
> Date: 2026-08-05

## Objective and scope

Start a focused v0.4 development line by making archived-session discovery an
explicit user choice and repairing first-time portable Go installation. The
version preserves Session Manager's append/update-only archive invariant: a
session already exported remains untouched when Codex later archives or removes
its raw source.

This version does not change archive layout, renderer, identity, attachment, or
configuration schemas. Native Codex resume, automatic Git mutation, and general
archive deletion remain outside scope.

## Work completed

### Archived-session export policy

- Changed ordinary discovery to scan active Codex `sessions/` only.
- Added the `IncludeArchived` export option. When enabled, discovery also scans
  `archived_sessions/` and maps a native session to the same device/session
  identity used while active.
- Kept existing archive entries independent of the current discovery set. A
  source archived or removed after export does not delete, rename, truncate, or
  rewrite its Markdown, attachments, sidecar, or derived list entry.
- Kept `cleanup-internal` scanning active and archived raw sources because it is
  a separate, explicit, dry-run-first operation with source and ownership proof.

### CLI and local GUI

- Added CLI `export --include-archived`, including command help and JSON-path
  integration.
- Added optional GUI API field `include_archived`; omitted or false retains the
  active-only default.
- Added an unchecked-by-default, bilingual GUI checkbox for including archived
  sessions and retained responsive dark-theme behavior.

### Portable build bootstrap

- Fixed the POSIX bootstrap to create `.tools/go` before publishing the first
  verified OS/architecture toolchain.
- Applied the equivalent parent-directory creation to the Windows PowerShell
  bootstrap without weakening existing checksum, lock, staging, or no-overwrite
  checks.

### Tests and documentation

- Added archive, CLI, and GUI/API regression coverage for default archived
  exclusion and explicit inclusion.
- Updated the retention regression to prove byte-for-byte preservation after an
  exported active source moves outside default discovery and later disappears.
- Updated README, PRD, SPEC, program version, and the devlog index for v0.4.

## Decisions and rationale

- **Archiving before export is an exclusion signal:** users can archive an
  unwanted Codex conversation before Session Manager sees it. Active-only
  discovery therefore provides the least surprising default.
- **Archived inclusion is explicit and per operation:** the CLI flag and GUI
  checkbox support historical backfill without creating persistent state that
  could unexpectedly include archived conversations on a later run.
- **Archive retention remains independent of discovery:** absence may mean Codex
  lifecycle management, not deletion authority. Ordinary export never derives a
  tombstone or prune operation from an omitted source.
- **Cleanup remains a separate authority boundary:** `cleanup-internal` retains
  archived raw-source discovery because its explicit `--apply` flow and strict
  ownership verification are unrelated to ordinary export selection.
- **Bootstrap creates only the missing parent:** the repair preserves atomic
  publication into the final platform directory and all existing fail-closed
  checks.

## Compatibility and migration

- Program version advances from `0.3.0-dev` to `0.4.0-dev`.
- Default export discovery changes from active-plus-archived to active-only.
  Automation that needs the former behavior must add `--include-archived` or
  send `include_archived: true` to the GUI API.
- The CLI flag and GUI API field are additive. Omitted API data decodes to false.
- No persisted schema, archive layout, renderer, identity, attachment, or config
  migration is required. Existing archive bytes remain valid and retained.

## Known limitations and risks

- The changed Windows PowerShell clean-parent path was not executed natively in
  this iteration; only Windows cross-builds were run from macOS.
- Archived sources excluded by default are not included in the export result's
  `sources` count because they are outside discovery rather than filtered after
  parsing.
