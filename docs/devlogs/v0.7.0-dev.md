# Session Manager v0.7.0-dev Devlog

> Status: Development
> Date: 2026-08-15

## Objective and scope

Reduce repository-only build and release complexity without changing session
discovery, archive formats, safety checks, CLI compatibility, GUI behavior, or
the already-reviewed v0.6.0 tag. Contributors now bring a supported Go
toolchain, and local plus CI Windows release builds share one implementation.

This version does not remove legacy archive readers, migrations,
`cleanup-internal`, CLI aliases, safety tests, or persisted-data compatibility.

## Work completed

### Contributor toolchain

- Removed the POSIX and Windows automatic Go downloaders, wrapper launchers,
  checksum manifest, `make bootstrap`, and `make clean-tools`.
- Made `go` from `PATH` the Makefile default while retaining explicit `GO=...`
  override support and the existing no-CGO cross-platform targets.
- Updated the local Windows release builder to resolve the installed `go`
  executable directly.

### Release pipeline

- Split source validation/tests and Windows asset construction into Ubuntu and
  Windows jobs.
- Made the Windows job invoke `scripts/build-windows-release.ps1`, removing the
  duplicated icon generation, cross-build, PE, version-resource, runtime-version,
  and checksum implementation from workflow YAML.
- Preserved the independent publish job, read-only build permissions, checksum
  reverification, and tag-only release boundary.

### Repository scope

- Removed the repository-specific `export-codex-sessions` helper and tracked
  `sessions/README.md`; neither was part of the shipped application, README,
  tests, or CI.
- Advanced unstamped development builds to `0.7.0-dev` and updated current
  requirements and release-pipeline documentation.

## Decisions and rationale

- **Install Go instead of maintaining Go:** released users consume a standalone
  executable, while source contributors already need Git and GNU Make. Requiring
  Go 1.24+ removes two platform-specific downloaders, two launchers, pinned
  archive hashes, locking/staging code, and a repository-local toolchain state
  machine.
- **One Windows release builder:** keeping one reviewed PowerShell contract is
  smaller and less drift-prone than maintaining equivalent Bash and PowerShell
  implementations. GitHub Actions uses a native Windows runner for that step.
- **Compatibility is intentionally retained:** legacy readers and cleanup code
  protect user archives and require a separately designed major-version
  migration before removal.
- **v0.6.0 remains immutable:** its annotated tag continues to point to commit
  `4515830`; this v0.7 development work is not added to or substituted for that
  release.

## Compatibility and migration

- Program version advances from `0.6.0` to `0.7.0-dev` for unstamped builds.
- Runtime behavior, config schema, repository/session metadata, layout,
  renderer, export JSON, CLI flags, and archive bytes are unchanged.
- Source contributors and local release builders must now install Go 1.24+ on
  `PATH`; existing ignored `.tools/` caches are no longer read or managed.
- The v0.6.0 release commit and tag remain unchanged.

## Known limitations and risks

- The refactored workflow cannot be exercised until a future reviewed release
  tag; local action lint and native-script validation are required meanwhile.
- GitHub's Windows runner is slower than the former Ubuntu cross-build step, in
  exchange for using the exact same release implementation as local Windows.
- Removing repository-managed Go makes offline first builds the contributor's
  responsibility.

## Next steps

1. Validate the final workflow on the next release candidate without moving an
   existing tag.
2. Consider a separately scoped v1 migration before removing legacy layouts,
   CLI aliases, or `cleanup-internal`.
