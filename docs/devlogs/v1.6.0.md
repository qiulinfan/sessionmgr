# Session Manager v1.6.0 Devlog

> Status: Released
> Date: 2026-10-19

## Objective and scope

Let a CLI export read only recently active sessions instead of every session
on the machine. The default window is 30 days; the owner's daily backup will
use 7 days. GUI export behavior and the archive format are unchanged.

## Work completed

### CLI export

- `export --within PERIOD` accepts a day count (`30d`, `7d`), a Go duration
  (`12h`, `90m`), or `all`/`0` for no limit. The default is `30d`.
- `--session ID` ignores the window, so session anchors still export old
  conversations.

### Archive export

- `Options.Within` sets a cutoff of the export start minus the window. Native
  sources (Codex, Claude Code, DeepSeek, OMP) whose file modification time is
  before the cutoff are not read; OpenCode rows use their modified time.
- A Codex or Claude Code source outside the window is still read when another
  source of the same logical session is inside it, so an active long
  conversation keeps its older fragments.
- Built on the v1.5.1 compaction fix (`49e4b25`): an old `.jsonl.zst` Codex
  fragment resolves its session ID through the decoded header, so it is still
  read with an active conversation.
- Sources outside the window keep their previous checkpoint entry (or stay
  unrecorded), so a later wider export still treats them as new or changed.
- The result reports `within_since` (the cutoff) and `outside_window` (sources
  skipped by the window); `ignored_unchanged` no longer counts them.

## Decisions and rationale

- The window is not part of the checkpoint scope key. Changing it therefore
  does not force a full rediscovery; correctness comes from never recording
  the current state of a skipped source.
- File modification time is the activity signal because it is already read
  for every source and needs no parsing. A session whose file was touched
  without new messages is simply read and found unchanged.
- The library default stays zero (no limit), so the GUI and other library
  callers keep exporting everything.

## Compatibility and migration

- CLI behavior change: `export` without `--within` now skips sessions inactive
  for more than 30 days. Use `--within all` for the previous behavior.
- CLI JSON result gains the optional `within_since` string and the
  `outside_window` count. Existing fields keep their meaning except that
  `ignored_unchanged` excludes window-skipped sources.
- No checkpoint, metadata or renderer schema change.

## Known limitations and risks

- A window skips a session whose source file is old even if the archive copy
  is missing; run `--within all` (optionally with `--full-scan`) to backfill.
