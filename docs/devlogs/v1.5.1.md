# Session Manager v1.5.1 Devlog

> Status: Development
> Date: 2026-10-16

## Objective and scope

Export local DeepSeek Harness format-4 histories while preserving the existing
public CLI source selection and GUI-only scope.

## Work completed

- Discover the latest canonical DeepSeek generation in each session directory;
  read format 0 and 4 and compressed versioned logs. Reject conflicting encodings
  and unknown latest formats without silently selecting an old generation.
- Validate internal system/developer surface events without exporting their
  content; recognize current replacement sequence field names.

## Decisions and rationale

Installed DeepSeek Harness 0.2.0-rc.2 writes `session.v4.jsonl.zstd` and may retain
older generations. Its installed persistence/session-log modules confirmed the
canonical names and current event fields. Existing native logs are never migrated.

## Compatibility and migration

No metadata, renderer, config or result schema change. Format-0 logs remain
readable. GUI-only scope remains Codex, Claude Desktop and OpenCode Desktop;
DeepSeek requires a separate explicit source export. Broad CLI support for the other native sources is unchanged. The macOS app bundle and GitHub release assets are not rebuilt/published.

## Known limitations and risks

- Only DeepSeek format 0 and 4 are supported; an isolated latest v1-v3 or future
  generation fails explicitly. Native source migrations are not performed.
- Existing hosted-Git-only filtering and historical incomplete-source reporting remain unchanged.

## Next steps

1. Revalidate the DeepSeek native format after upstream changes.
2. Rebuild app bundles or publish a release only when requested.
