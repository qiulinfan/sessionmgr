# Session Manager v1.5.1 Devlog

> Status: Development
> Date: 2026-10-16 (updated 2026-10-19)

## Objective and scope

Export local DeepSeek Harness format-4 histories while preserving the existing
public CLI source selection and GUI-only scope.

2026-10-19: stop Claude Code and Codex exports from losing their earlier
conversation (and renaming their semantic directory to a later start time)
after context compaction or rollout compression.

## Work completed

- Discover the latest canonical DeepSeek generation in each session directory;
  read format 0 and 4 and compressed versioned logs. Reject conflicting encodings
  and unknown latest formats without silently selecting an old generation.
- Validate internal system/developer surface events without exporting their
  content; recognize current replacement sequence field names.
- Claude Code: follow `logicalParentUuid` at `system/compact_boundary` records,
  whose `parentUuid` is null. The export now spans every compaction and
  `CreatedAt` is the real first record, so the semantic directory no longer
  moves to the latest compaction time. `isCompactSummary` user records are
  generated context and are filtered, not exported as user input. A boundary
  stays the root (old behavior) when its logical parent is absent or written
  only after it: transcripts resumed from a compacted state begin with a copied
  boundary, and following it there would form a parent cycle.
  No compaction marker is rendered: the renderer has only user/assistant roles,
  and adding one would change the document format.
- Codex: discover `.jsonl.zst` rollout fragments as well as `.jsonl`, decode them
  with `klauspost/compress/zstd` after the unchanged stability read, then apply
  the usual completed-prefix and raw hash. A plain `.jsonl` beside its `.zst`
  wins, so a fragment is never read twice. Session-ID peeking (incremental and
  sidebar scope) and `cleanup-internal` read compressed fragments too.

## Decisions and rationale

The Codex fragment hash is over the decoded JSONL, unlike DeepSeek's hash over
compressed bytes: Codex compresses an existing fragment in place of the plain
file, and hashing decoded bytes keeps that transition a no-op instead of a
logical-session update. Codex frames carry no checksum, so DeepSeek's frame
validation is not reused.

Installed DeepSeek Harness 0.2.0-rc.2 writes `session.v4.jsonl.zstd` and may retain
older generations. Its installed persistence/session-log modules confirmed the
canonical names and current event fields. Existing native logs are never migrated.

## Compatibility and migration

No metadata, renderer, config or result schema change. Format-0 logs remain
readable. GUI-only scope remains Codex, Claude Desktop and OpenCode Desktop;
DeepSeek requires a separate explicit source export. Broad CLI support for the other native sources is unchanged. The macOS app bundle and GitHub release assets are not rebuilt/published.

The 2026-10-19 parser fixes change no schema. On the next export, affected
Claude and Codex sessions get full documents and existing archive entries are
renamed to the directory of their real start time through the usual verified
update path; compaction summaries leave the exported user messages.

## Known limitations and risks

- Only DeepSeek format 0 and 4 are supported; an isolated latest v1-v3 or future
  generation fails explicitly. Native source migrations are not performed.
- Existing hosted-Git-only filtering and historical incomplete-source reporting remain unchanged.
- Reading `.jsonl.zst` exposes older Codex sessions that were never exported.
  In the native check two of them hit existing safety refusals (a modified
  archived document is not overwritten; two non-Git directories share one
  semantic name). They need a separate decision.
- Claude compaction is not marked in the rendered conversation.
