# Session Manager v1.4.2 Devlog

> Status: Released
> Date: 2026-10-07

## Objective and scope

Stop reporting interrupted historical logs and generated engine CLI tasks as
concurrent user conversations. Preserve native files and existing document hashes.

## Work completed

- Codex recognizes explicit turn abortion without losing later completed turns.
  An aborted history with no completed turn is incomplete, rather than busy.
- Stable parser-incomplete sources older than one hour have distinct diagnostics
  with harness, session ID, reason, and last activity. Age is a retry policy, not
  proof that a runtime has stopped.
- Checkpoints retain incomplete diagnostics while deferring unchanged sources.
  Size, modification time, title metadata changes, or a full scan resume reads.
- A readable logical copy supersedes a deferred incomplete physical copy;
  incomplete counts deduplicate logical session IDs.
- OpenCode generated engine jobs in OS temporary pocket-eval, pocket-agent,
  pocket-play, pocket-debug-eval directories and Claude scratchpads are filtered
  before completion parsing, even without OpenCode parent IDs. macOS /private
  path aliases are covered. Ordinary checkout names are not filtered.
- CLI JSON includes incomplete and source_issues. WebUI distinguishes stable
  incomplete histories and avoids claiming every busy source is actively running.
- Companion private sessions backup helper accepts JSON schemas 4 and 5 and
  refuses completeCapture when stable incomplete histories remain.

## Decisions and rationale

Interrupted sources are retained, not fabricated into completed conversations.
Known generated-directory evidence is deliberately narrow: OpenCode lacks a
cross-harness parent link, so arbitrary CLI provenance cannot be inferred.
Permanent parse corruption and publication/hash conflicts retain existing retries.

## Compatibility and migration

Export receipt schema is 5; fields are additive, strict consumers must update.
Checkpoint schema 2 accepts and upgrades schema 1 without resetting scope or
hash records. Older binaries cannot read the upgraded checkpoint; do not downgrade
without preserving the checkpoint separately. Archive/document formats unchanged.

## Known limitations and risks

- No claim that an old unfinished source's process exited; changing sources and
  recently incomplete sources continue to retry.
- Stable incomplete histories are diagnosed, not exported as completed answers.
- Generic cross-harness CLI calls outside known generated directories remain
  indistinguishable from direct user OpenCode sessions.
- No normalization or hash repair; previously modified/missing exports remain.
- Release assets are built and published by the tagged GitHub Actions workflow.
  Linux and Windows native runtime checks are limited to the release workflow.
