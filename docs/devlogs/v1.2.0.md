# Session Manager v1.2.0 Devlog

> Status: Released
> Date: 2026-09-30

## Objective and scope

Archive conversations whose recorded workspace has been deleted, reduce repeat
export work using local scan history, reveal exported Markdown from the UI,
and package a native macOS app alongside the Windows release. Existing Markdown
rendering and document-hash ownership checks are unchanged, as requested.

## Work completed

### Workspace identity

- Missing absolute native CWDs identify device-local directories when non-Git
  inclusion is enabled. No native directory is recreated and no hosted remote
  is inferred from a directory name.
- Resolve surviving parent aliases so deletion preserves identity, including
  macOS `/var` and `/private/var`. Explicit current-directory scope still
  requires an accessible directory.

### Incremental export

- CLI/GUI save schema-v1 `export-state.json` beside local config, outside the
  shared archive. Output/device/source/scope/policy selections have independent
  checkpoints.
- Record scan start and recheck a one-hour overlap. Older unchanged JSONL
  payloads are excluded; new paths, changed size/mtime, Codex title changes,
  and pending failures stay eligible, including backdated copies.
- Read all known members of an eligible logical Codex/Claude session. An
  unreadable known member blocks partial bundle publication and stays pending.
  Partial exports advance time while retaining failed and busy sources.
- OpenCode compares headers and latest session/message/part timestamps before
  reading payloads. Active tails stay pending while prior completed turns
  remain exportable.
- Added CLI `--full-scan`, GUI full scan, last export time, and scan counts.
  Library callers without a checkpoint path retain full-scan behavior.

### Browser interface

- Session titles are keyboard-accessible buttons. Token-protected reveal only
  accepts successful exports from that GUI process, verifies a regular file
  inside its archive, and rejects parent/file symlink escapes.
- macOS uses `open -R`; Windows uses Explorer selection; Linux opens the
  containing directory with `xdg-open`.
- Remove the private readiness token from the visible URL after storing it in
  the current tab's session storage; reload still authenticates locally.

### macOS app and release packaging

- Added a small AppKit/WKWebView launcher using macOS system frameworks. It
  embeds the existing interface, starts its bundled server without a terminal,
  keeps the readiness token in memory, and stops its child when the app quits.
- Dock reopen activates the existing window. Edit and Reload menus support
  normal text interaction; automatic navigation stays on the app's own
  loopback server and explicit HTTPS links open in the system browser.
- Added a reproducible macOS builder for universal arm64/x86_64 launcher and
  backend binaries, the existing PNG-derived app icon, versioned Info.plist,
  ad-hoc integrity signatures, a portable zip and SHA-256 checksum.
- Release CI builds the macOS app and Windows executables after source
  validation; publication waits for both build jobs. No signing credentials
  or Apple account are introduced.

## Decisions and rationale

- Use metadata for filtering rather than hashing every old source. Remember
  unseen and pending sources so copied history is included and an old conflict
  does not prevent incremental progress for all other sessions.
- Isolate checkpoints by selection so enabling non-Git/archived sources or
  changing output includes historical sessions on the first scan.
- Preserve non-Git opt-in and ownership checks. Keep mutable times out of
  Markdown and archive sidecars to avoid manufacturing Git changes.

## Compatibility and migration

- Source version is `1.2.0`; released v1.1.0 history remains immutable.
- Config v3, repository v1/v2, session v2, layout v5, attachment v1, and
  renderer v9 remain unchanged.
- Export-result schema advances to v4, retaining prior fields and adding
  `scanned_sources`, `ignored_unchanged`, `incremental`, optional `since` and
  `last_export_at`.
- Local checkpoint schema v1 is created on first export. Missing state starts
  a full scan; unknown schema/fields fail closed. Atomic temp/fsync/rename
  publication and in-process export serialization protect updates.
- Non-Git full publication applies to selected candidates. Old unchanged
  sources can be omitted by time filtering; `--full-scan` restores discovery.
- macOS 14+ receives one universal `.app` in the release zip. The app shares
  the existing local config and scan state. App launch arguments are forwarded
  to its bundled GUI backend; the CLI remains independently usable.

## Known limitations and risks

- Discovery still lists sources and reads archive sidecars. Savings come from
  avoiding old transcript decoding, repository checks and rendering.
- In-place edits with unchanged size and restored mtime outside the overlap
  require a full scan. Native append/update normally changes one or both.
- Separate CLI processes atomically replace checkpoints without cross-process
  merging. Avoid simultaneous CLI exports to the same checkpoint.
- Reveal applies to exports from the current GUI process. Linux opens a folder
  without promising desktop-specific file selection. Live Windows/Linux file
  manager integration needs those hosts; command tests/cross-builds are not
  desktop runtime evidence.
- The diagnosed Git CRLF normalization conflict remains subject to existing
  overwrite refusal. No newline/hash repair is included.
- The macOS bundle has ad-hoc signatures but no Developer ID signature or Apple
  notarization. Windows executables remain without Authenticode signatures.
- Native macOS behavior was exercised on Apple Silicon; the Intel slice was
  compiled, packaged and signature-verified but not executed on an Intel Mac.

## Next steps

1. Verify Explorer and Linux desktop integration on their native hosts.
2. Add Developer ID signing/notarization only when the owner supplies the
   appropriate credentials and authorizes that release configuration.
