# Session Manager v1.9.0 Devlog

> Status: Development
> Date: 2026-10-29

## Objective and scope

OMP no longer keeps GUI clients' sessions in a separate `sessions-gui`
directory: Zed, IINA and omp gui now share OMP's own store, so the TUI, omp gui
and `omp --resume` see every session. Each new session's header names the
front end that started it (`origin`). GUI-only export must keep selecting GUI
conversations from that shared store: every session a GUI started, none the CLI
or an automation started.

## Work completed

### OMP source

- GUI-only export reads `<omp-home>/sessions` (or the configured session
  directory) like a full export and keeps a session when its header's
  `origin.client` is `omp-gui`, `zed` or `iina` and the file sits directly in a
  project folder. Both exports also read omp gui's chats in
  `<omp-home>/sessions-chats`, which GUI-only export keeps whole. `ompGUISession`,
  `ompChatSessionDir` and `peekOMPHeader` in `internal/archive/omp.go`
  implement it.
- OMP no longer reads Zed's sidebar: the Zed fork now adds every session its
  agents list to the sidebar by itself, so sidebar membership no longer means a
  conversation held in Zed.
- Removed the `--omp-gui-session-dir` flag and `Options.OMPGUISessionDir`: no
  client writes a separate GUI directory any more.

## Decisions and rationale

- The owner's rule: GUI conversations are exported, CLI ones are not. The
  header origin, written when a session starts and never changed, decides it,
  so a CLI session continued in Zed or omp gui stays out.
- omp gui's desktop app, browser page and its Obsidian and VS Code side bars
  share one server and one origin (`omp-gui`); Zed and IINA reach OMP over ACP
  under their own client names. One file per session means one export each.
- Subagents carry their parent's origin but live in nested folders, so only a
  project folder's own transcripts count.

## Compatibility and migration

- `--omp-gui-session-dir` is removed; callers passing it get an unknown-flag
  error. The private `sync-sessions` helper does not pass it.
- Sessions written by an OMP without `origin` are not GUI conversations to
  GUI-only export, except omp gui's chats. The owner's earlier `sessions-gui`
  and `sessions-iina` files moved into the shared store with an `origin`
  added.

## Known limitations and risks

- The Windows and WSL paths were not exercised; they share the same code.
