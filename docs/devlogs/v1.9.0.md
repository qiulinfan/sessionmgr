# Session Manager v1.9.0 Devlog

> Status: Development
> Date: 2026-10-29

## Objective and scope

OMP no longer keeps GUI clients' sessions in a separate `sessions-gui`
directory: Zed, IINA and omp gui now share OMP's own store, so the TUI, omp gui
and `omp --resume` see every session. Each new session's header names the
front end that started it (`origin`). GUI-only export must keep selecting GUI
conversations from that shared store. Out of scope: exporting IINA's sessions,
which GUI-only export did not include before either.

## Work completed

### OMP source

- GUI-only export reads `<omp-home>/sessions` (or the configured session
  directory) like a full export and keeps a session when Zed's thread sidebar
  lists it unarchived (as before, whatever started it) or when its header's
  `origin.client` is `omp-gui` and the file sits directly in a project folder.
  `ompGUISession` and `peekOMPHeader` in `internal/archive/omp.go` implement it.
- Removed the `--omp-gui-session-dir` flag and `Options.OMPGUISessionDir`: no
  client writes a separate GUI directory any more.

## Decisions and rationale

- Zed membership stays decided by Zed's sidebar, not the header: a session
  started in the TUI and continued in Zed is a Zed conversation, and Zed keeps
  a deleted thread's file.
- omp gui has no list of its own to consult, so its sessions are selected by
  the header origin. Its subagents carry the same origin but live in nested
  folders, so only a project folder's own transcripts count.

## Compatibility and migration

- `--omp-gui-session-dir` is removed; callers passing it get an unknown-flag
  error. The private `sync-sessions` helper does not pass it.
- Sessions written by an OMP without `origin` are exported by GUI-only export
  only when Zed lists them. The owner's earlier `sessions-gui` and
  `sessions-iina` files move into the shared store with an `origin` added.

## Known limitations and risks

- The Windows and WSL paths were not exercised; they share the same code.
