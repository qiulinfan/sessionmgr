# Session Manager v0.6.0-dev Devlog

> Status: Development
> Date: 2026-08-15

## Objective and scope

Add explicit, read-only export support for top-level DeepSeek Harness sessions
without changing the default Codex-only workflow, and make the resulting v0.6
application directly downloadable as versioned Windows AMD64/ARM64 executables.
Selected DeepSeek sessions must pass the same repository identity, redaction,
attachment, owned-file, incremental publication, and append/update-only archive
boundaries as Codex sessions while respecting DeepSeek's native format and
provenance. Windows release publication must be reproducible, checksum-backed,
and gated by the full validation suite.

This version does not add DeepSeek native resume/replay, subagent export,
automatic Git mutation, mirror deletion, DeepSeek-derived cleanup, a Windows
installer/service, or Authenticode signing.

## Work completed

### DeepSeek source adapter

- Added opt-in discovery below `DSH_HOME/sessions`, accepting exactly one
  `session.jsonl.zstd` or `session.jsonl` per native session directory.
- Added format-v0 header validation, top-level provenance classification,
  contiguous event-sequence checks, and packed text/reasoning/tool-call row
  validation.
- Added pure-Go decoding for concatenated Zstandard frames with per-frame
  checksum requirements, decoder checksum validation, a 512 MiB decoded-size
  cap, and distinct busy handling for torn frames or incomplete JSONL tails.
- Projected only append-surface direct user messages and model assistant text.
  Plugin-injected user records, replacement surfaces, reasoning, tool payloads,
  and subagent sessions remain outside the human transcript.
- Folded the latest `session/title` event and retained native event timestamps
  for the exported timeline.

### Attachments and safety

- Resolved DeepSeek image references only through the native content-addressed
  `attachments/v1/objects` layout.
- Added expected SHA-256 and byte-size checks after the existing stable,
  no-symlink attachment read and before publication.
- Kept native DeepSeek session files and attachment objects read-only; raw
  compressed bytes remain the `source_hash` authority.

### Identity, metadata, and rendering

- Preserved the established Codex session-key algorithm and introduced a
  harness-qualified key only for DeepSeek, preventing cross-harness native-ID
  collisions without migrating existing Codex identities.
- Added a `deepseek--` semantic-directory namespace to prevent visible path
  collisions when two harnesses share a creation time and title.
- Advanced session metadata to schema v2 with a required `harness` for new
  records. The reader continues to accept schema-v1 sidecars as implicit Codex
  records and upgrades them only during a verified publication.
- Advanced renderer to v7 and added harness provenance to Markdown, list output,
  and changesets. Export result JSON is now schema v3.

### CLI and local GUI

- Advanced the program version to `0.6.0-dev`.
- Added `export --include-deepseek` and `--deepseek-home`; the latter follows
  explicit path, `DSH_HOME`, then `~/.dsh` precedence.
- Added the DeepSeek home override to `gui` and an independent bilingual GUI
  checkbox/API field `include_deepseek`.
- Added a `HARNESS` column to human-readable `list` output and harness labels to
  GUI change cards.

### Windows release distribution

- Made the development version linker-overridable while keeping
  `0.6.0-dev` as the explicit unstamped default.
- Added a tag-only GitHub Actions workflow that verifies dependencies, runs
  vet, tests, and the race detector, then builds version-stamped Windows AMD64
  and ARM64 PE executables.
- Added SHA-256 generation, a one-day handoff artifact, checksum reverification,
  and guarded `gh release create --verify-tag` publication after all validation
  and binary checks have succeeded. Only the final publish job receives
  `contents: write`; build and test retain read-only repository access.
- Added a local PowerShell release builder that uses the same linker target,
  filenames, PE check, native version execution, and checksum contract.
- Documented the portable Windows launch flow and the current lack of
  Authenticode signing so checksum verification is not confused with publisher
  identity.

### Tests and documentation

- Added parser coverage for concatenated frames, checksums, truncated input,
  incomplete decompressed JSONL, event gaps, packed rows, title folding,
  plugin filtering, subagent filtering, and image references.
- Added archive, CLI, GUI/API, renderer, sidecar-upgrade, cross-harness identity,
  idempotence, list provenance, and raw-source immutability regressions.
- Updated README, PRD, SPEC, program version, dependency metadata, and the
  devlog index for v0.6.

## Decisions and rationale

- **DeepSeek is opt-in:** existing invocations retain Codex-only discovery and
  do not incur another state-root scan.
- **Raw logs remain authoritative:** normalized messages are derived for human
  reading; neither they nor archive sidecars replace DeepSeek's native bytes.
- **Append source events define the transcript:** replacement surfaces describe
  mutable UI state and plugin sources are not direct human input. Keeping only
  direct append events gives a stable, auditable conversation history.
- **Compression integrity fails closed:** current DeepSeek compressed sessions
  are concatenated checksum-bearing frames. A missing or bad checksum is
  corruption, while a structurally incomplete final frame is a retryable busy
  source.
- **Compatibility is harness-specific:** changing the long-lived Codex key or
  directory layout would create duplicate archives. DeepSeek receives the new
  discriminator and visible prefix instead.
- **DeepSeek cleanup is excluded:** `cleanup-internal` has a Codex-specific raw
  proof contract. Extending deletion authorization requires a separate design
  and is not implied by adding read-only export.
- **Release publication is tag-gated:** a strict semver tag is a deliberate
  external publication action. The workflow cannot publish from an ordinary
  branch push. It additionally requires matching source-version and Released
  devlog evidence, and reaches `gh release create` only after every validation
  and artifact-integrity step passes.
- **Portable exe before installer/signing complexity:** the existing single
  binary already contains the GUI and loopback server. Shipping that binary
  serves Windows users immediately without adding an installer, service, or
  hidden background lifecycle. Authenticode can be added later when a signing
  identity and protected secret are available.

## Compatibility and migration

- Program version: `0.6.0-dev`.
- Tagged release builds override only the reported program version; schemas,
  behavior, and persisted formats are identical to the tagged source commit.
- Config schema remains v1; repository metadata remains hosted schema v1 or
  local-directory schema v2; layout remains v5; attachment schema remains v1.
- Renderer advances from v6 to v7. Existing owned Codex documents receive one
  verified update when exported again.
- Session metadata advances from schema v1 to v2. Schema-v1 records are accepted
  only as implicit Codex and retain their established key; schema-v2 records
  require `codex` or `deepseek`.
- Export result JSON advances from schema v2 to v3, and each change now includes
  required `harness`. JSON consumers must accept the new schema before using
  v0.6 automation.
- Existing Codex archive paths and session keys are unchanged. DeepSeek uses a
  new harness-qualified key and `deepseek--` semantic path prefix.
- A v0.5 binary will fail closed when it encounters a schema-v2 DeepSeek session
  sidecar; it will not overwrite the entry.

## Known limitations and risks

- The adapter targets DeepSeek Harness session format v0 as shipped by the
  installed `@deepseek-ai/dsh 0.1.0-rc.6`. The upstream format is prerelease;
  a future required event or header semantic may need an explicit adapter
  update.
- Only native image attachment blocks are exported. No free-text paths, tool
  data, remote downloads, or speculative additional content types are captured.
- Decoded DeepSeek session content is capped at 512 MiB and one native session
  directory may not contain both supported encodings.
- DeepSeek has no Codex-style archived-session option. `--include-archived`
  remains Codex-only, and `cleanup-internal` remains Codex-only.
- Native Windows symlink safety tests require `CreateSymbolicLink` privilege;
  validation records whether they were run in a privilege-capable environment.
- Windows release executables are not Authenticode-signed. SmartScreen may warn
  until a publisher certificate and protected CI signing path are configured.
- The GitHub tag workflow has been statically validated but not triggered in
  this change. Creating the public Release still requires an explicit reviewed
  commit and `vMAJOR.MINOR.PATCH` tag push.
