# Session Manager v1.8.0 Devlog

> Status: Development
> Date: 2026-10-24

## Objective and scope

GUI-only export covers every conversation the owner holds in a GUI: Claude
Desktop, the Claude Code side panel of VS Code, and the OMP and Claude Agent
threads of Zed, on macOS, Windows and WSL. Each GUI's own list now decides
membership, so archiving or deleting a conversation there takes it out of later
exports, and a CLI run started inside a GUI session no longer passes for one. A
Windows machine and its WSL distribution share a host name, so a device can now
be named explicitly and each keeps its own export directory. Running a WSL
export from Windows, and the daily backup schedule itself, belong to the private
`sessions` repository's `sync-sessions` helper, not to this product.

## Work completed

### Export

- VS Code side panel: `export --gui-only` keeps Claude Code transcripts whose own
  session records carry `entrypoint=claude-vscode`, the value the VS Code
  extension sets for the Claude process it starts, except those the extension
  archived. It records them in the `hiddenSessionIds` of the
  `Anthropic.claude-code` entry in VS Code's global state database, read with
  `--vscode-state` (default `Code/User/globalStorage/state.vscdb` under the
  platform's configuration folder; `internal/archive/vscode.go`).
- Claude Desktop: a `claude-desktop` transcript counts only while Claude
  Desktop's own session records list it unarchived, as the `cliSessionId` or one
  of the `priorCliSessionIds` of a `claude-code-sessions/**/local_*.json` record
  in the app's data folder (`--claude-desktop-data`, default the folders the app
  names; `internal/archive/claude_desktop_registry.go`). The receipt's
  `claude_desktop_sessions` names the folders read. `--desktop-only` uses the
  same list.
- Zed: OMP sessions under `<omp-home>/sessions-gui` count only while Zed's
  thread sidebar lists them unarchived under the custom agent `OMP`, as Claude
  Agent threads already did under `claude-acp` (`internal/archive/zed.go`,
  `omp.go`, `archive.go`).
- Sidechains, agent IDs, teleported records and copied ancestry stay out as
  before.

### Configuration

- `sessionmgr config set-device-name NAME` stores the device name used in export
  paths; the device ID is kept (`internal/config/config.go`, `internal/app/app.go`).
  A new home still starts from the host name.

## Decisions and rationale

- A CLI run started from a shell inside a Claude Desktop session inherits
  `CLAUDE_CODE_ENTRYPOINT=claude-desktop`; on this Windows machine four such
  `claude -p` checks were being exported as Desktop conversations. Their records
  carry no other mark, so membership comes from the app's own session list, as
  it already did for Zed's sidebar and Codex's thread inventory.
- Archiving is the owner's way to say a conversation is done in every GUI that
  has it (Codex, Claude Desktop, VS Code, Zed), so an archived conversation
  leaves later exports; what is already exported stays.
- Zed deletes a Claude Agent transcript with its thread but leaves an OMP
  session's file in place, so the OMP directory alone cannot follow a deletion;
  the sidebar can.
- The Claude Desktop data folder is located by the names and places the app
  itself documents (Claude-Data, Claude-3p or Claude under `%LOCALAPPDATA%` or
  `%APPDATA%`, `~/Library/Application Support`, `~/.config`), with the session
  folder at the top or one level down, where the packaged Windows app keeps a
  `claude_<package>` folder. Without such a folder no Desktop session is in
  scope rather than every one.
- WSL is exported by its own Session Manager home inside the distribution, with
  native Linux paths, rather than by teaching the Windows binary to read WSL homes
  and translate `/home` and `/mnt/c` working directories: repository resolution
  then runs WSL's own Git on paths it understands.

## Compatibility and migration

- GUI-only exports may now include `claude-vscode` sessions that earlier versions
  filtered, and leave out Claude Desktop sessions the app does not list or has
  archived, OMP sessions Zed does not list or has archived, and VS Code sessions
  archived in the extension. Exports already written stay in the archive.
- No schema, receipt or path format changed; the receipt gains the optional
  `claude_desktop_sessions` field.
- `config.json` gains no new field: `device_name` already existed and is only
  writable by command now.

## Known limitations and risks

- The VS Code extension keeps no list of the sessions it started, so a CLI run
  started from a shell inside a VS Code session still counts as a side-panel
  conversation.
- The Claude Desktop, VS Code and Zed lists are internal formats of those apps;
  a change there fails the export rather than guessing.
