# Session Manager v1.8.0 Devlog

> Status: Development
> Date: 2026-10-24

## Objective and scope

GUI-only export also archives the Claude Code conversations of the VS Code
extension's side panel, so every conversation the owner holds in an editor's
side panel (VS Code, and Zed since 1.7.0) is backed up on macOS, Windows and
WSL. A Windows machine and its WSL distribution share a host name, so a device
can now be named explicitly and each keeps its own export directory. Running a
WSL export from Windows, and the daily backup schedule itself, belong to the
private `sessions` repository's `sync-sessions` helper, not to this product.

## Work completed

### Export

- `export --gui-only` keeps Claude Code transcripts whose own session records
  carry `entrypoint=claude-vscode`, the value the VS Code extension sets for the
  Claude process it starts, next to Claude Desktop roots and the Claude Agent
  threads Zed lists (`internal/archive/claude_desktop.go`, `archive.go`).
  Sidechains, agent IDs, teleported records and copied ancestry stay out exactly
  as for Desktop sessions.
- The legacy `export --desktop-only` scope is unchanged: it still means Codex
  sidebar roots and Claude Desktop roots only.

### Configuration

- `sessionmgr config set-device-name NAME` stores the device name used in export
  paths; the device ID is kept (`internal/config/config.go`, `internal/app/app.go`).
  A new home still starts from the host name.

## Decisions and rationale

- The VS Code extension has no sidebar registry that an exporter could read, so
  every root `claude-vscode` session is in scope; unlike Zed, archiving or
  deleting a conversation in the editor does not remove it from scope.
- WSL is exported by its own Session Manager home inside the distribution, with
  native Linux paths, rather than by teaching the Windows binary to read WSL homes
  and translate `/home` and `/mnt/c` working directories: repository resolution
  then runs WSL's own Git on paths it understands, and no path translation or
  second home of each kind is needed in the product.

## Compatibility and migration

- GUI-only exports may now include `claude-vscode` sessions that earlier versions
  filtered; no schema, receipt or path format changed.
- `config.json` gains no new field: `device_name` already existed and is only
  writable by command now.

## Known limitations and risks

- A VS Code conversation the owner deletes in the extension stays exported.
- The real VS Code extension's transcripts were not yet available on this
  machine at the time of writing; the entrypoint value was read from the
  extension's source, and the behavior is covered by fixtures.
