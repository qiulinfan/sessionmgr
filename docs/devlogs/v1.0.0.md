# Session Manager v1.0.0 Devlog

> Status: Released
> Date: 2026-08-20

## Objective and scope

Add read-only export support for top-level Claude Code sessions while
preserving the established identity,
redaction, attachment, owned-file, incremental publication, and
append/update-only safety boundaries.

Codex, Claude Code, and DeepSeek Harness are peer optional sources. CLI export
automatically scans all available native roots. The GUI presents three switches
at the top, initializes them from first-open source detection, remembers user
choices locally, and permits any or all sources to be disabled.

Claude Code parsing remains deliberately fail-closed because Anthropic documents the
transcript location but also states that the JSONL entry format is internal and
may change on any release. The adapter must therefore validate structure, omit
runtime-only content, and fail closed instead of presenting an unknown format as
a successful export.

This version does not add Claude Code native resume/import, invocation of Claude
Code or `/export`, cloud or Claude Desktop history, subagent export, complete
tool traces, checkpoint/file-history export, automatic Git mutation, mirror
deletion, or Claude-derived cleanup.

### Official Claude Code evidence

- Anthropic documents local transcripts at
  `~/.claude/projects/<project>/<session-id>.jsonl`, with
  `CLAUDE_CONFIG_DIR` as the storage-root override.
- Anthropic documents each transcript as plaintext JSONL containing messages,
  tool calls, tool results, and metadata, and warns that the entry format is an
  internal implementation detail that can change on any release.
- Anthropic documents `~/.claude/sessions/` as running-session/crash-detection
  state rather than conversation transcripts; it must not be scanned as a
  source.
- Anthropic documents top-level session transcripts separately from
  `<session>/subagents/`, `<session>/tool-results/`, file history, prompt history,
  and other application data. Those adjacent stores remain out of scope.
- Anthropic documents resume as appending to the same session ID, fork/branch as
  creating a separate session ID, rewind as retaining original transcript
  messages, and `/cd` as relocating session storage to the new project directory.
- Anthropic documents user-provided names as taking precedence over generated
  titles, with first-prompt fallback in the session picker.

### Read-only local format study

- Inspected the shape of 41 top-level Claude Code session JSONL files across
  five local project directories without printing project paths, transcript
  text, session IDs, settings, authentication state, or environment values.
- Parsed 35,379 lines with zero invalid JSON records. The files contained 31,398
  UUID-addressed nodes, exactly one native session ID per file, and a filename
  matching that native ID in all 41 cases.
- Found exactly one parentless UUID node per file and no missing parent
  references, but 4,533 branching parent nodes and 4,575 leaf nodes. Following
  the last UUID-bearing record back through `parentUuid` selected 25,214 nodes,
  or 80.3% of all UUID nodes. This confirms that file order alone would mix
  abandoned rewind/branch paths into the readable conversation.
- In every sampled file the last UUID-bearing record was a leaf. Every known
  `last-prompt.leafUuid` was an ancestor of that leaf. This supports, but does
  not make an upstream guarantee of, choosing the last appended UUID leaf as
  the current conversation branch.
- Observed direct human records, task notifications, tool-result user records,
  `isMeta` records, local-command envelopes, IDE context blocks, assistant text,
  thinking, tool use, API-error/synthetic assistant records, generated titles,
  explicit agent names, relocations, system records, and runtime attachment
  records.
- Observed user message blocks containing text, one base64 PNG image, and three
  text-backed document blocks. Tool results and Claude runtime attachment
  records were far more numerous but are not direct user attachments.
- Observed repeated adjacent assistant records sharing one `message.id`; all
  repeated IDs were contiguous on the selected ancestry chain. Grouping them
  reconstructs one assistant turn while allowing thinking and tool-use blocks
  to be counted and omitted.

### Implemented adapter contract

The implementation follows this contract:

1. Resolve the Claude state root from explicit `--claude-home`, then
   `CLAUDE_CONFIG_DIR`, then `~/.claude`; expand `~` consistently with the
   DeepSeek resolver.
2. Discover only regular files matching `projects/*/*.jsonl`. Do not recursively
   scan project directories. This excludes memory, per-session subagents,
   workflows, tool results, and other application data by construction.
3. Share the existing batch stability window with Codex and DeepSeek sources.
   Require unchanged file identity/size/mtime before, during, and after reading,
   and classify an incomplete final JSONL record as retryable `busy`.
4. Require one non-empty session ID per file and require it to equal the JSONL
   filename stem. Reject duplicate UUIDs, missing parents, multiple roots, parent
   cycles, invalid timestamps in required message nodes, or inconsistent
   top-level session identity.
5. Preserve every UUID-bearing node in the graph long enough to validate it.
   Choose the final UUID-bearing record in source order, require it to be a leaf,
   follow `parentUuid` to the single root, and render that ancestry in root-to-leaf
   order. Count off-ancestry UUID nodes as omitted alternate-branch records.
   Never sort conversation nodes by timestamp because real transcripts contain
   timestamp regressions.
6. Treat a top-level source as internal when structured sidechain/agent
   provenance says it is a subagent. Directory discovery already excludes the
   documented `subagents/` layout, but provenance remains a second fail-closed
   boundary.
7. Include user records only when they represent direct human input. Exclude
   `toolUseResult`/`sourceToolAssistantUUID`, `isMeta`, task-notification,
   local-command output, interrupt markers, and runtime/system envelopes. Strip
   exact standalone IDE context blocks such as `ide_opened_file` while retaining
   the human text and structured attachments in the same message. Legacy records
   without structured provenance are accepted only when their known message
   shape is direct and no internal envelope matches; unknown provenance blocks
   the source rather than leaking likely runtime context.
8. Group contiguous assistant records by native `message.id`. Preserve the first
   group position and timestamp, concatenate visible text blocks in source order,
   count `tool_use` blocks, and omit thinking, signatures, tool input/output,
   synthetic messages, and API-error diagnostics. A repeated assistant ID after a
   different assistant ID is a structural error until explicitly supported.
9. Select title precedence as latest non-empty explicit `agent-name`, then latest
   non-empty `ai-title`, then the first sanitized direct human text, then
   `Claude Code session <id>`. Title records have no trustworthy timestamp in the
   observed format, so do not manufacture `title_updated_at` from file mtime.
10. Select the current CWD and Git branch from the last non-empty values on the
    chosen ancestry, honoring a structured relocation record when present. Do
    not decode the project-directory name into a path and do not guess a commit
    from the current worktree, because neither value is a reliable transcript
    fact.
11. Export only structured image/document blocks attached to direct human
    messages. Decode base64 image bytes with the existing 50 MiB limit. Preserve
    text-backed document data as the exact embedded bytes with its declared
    title and media type; do not claim that derived text is the original source
    file. Do not read `paste-cache`, `image-cache`, `tool-results`, free-text
    paths, or remote URLs to reconstruct missing bytes.
12. Reuse the existing attachment redaction/sensitivity checks, semantic file
    naming, owned-file verification, sidecar-last publication, and non-Git full
    export behavior. Claude sources and embedded data remain read-only.
13. Use required harness value `claude-code`, the existing non-Codex
    harness-qualified session-key algorithm, and visible semantic prefix
    `claude-code--`. Because native Claude forks copy creation time and title,
    append an 8-hex deterministic session-key variant to every Claude semantic
    directory. Existing Codex/DeepSeek keys and paths remain unchanged.
14. Advance config schema to v2 for optional GUI source preferences; accept v1
    read-only and migrate on the next authorized config write. Keep repository schema v1/v2, session metadata schema v2,
    attachment schema v1, layout v5, and export-result schema v3. Expand the
    session schema-v2 harness enum to `claude-code`. Advance renderer to v8 so
    Markdown records the new harness and `claude_code_version`; verified existing
    documents receive the same one-time renderer update behavior used by prior
    renderer advances.
15. CLI automatically scans all three homes and accepts `--claude-home` without
    any harness include flag. GUI uses top-level Codex/Claude/DeepSeek switches
    and request object `sources.{codex,claude_code,deepseek}`. First-open detected
    availability initializes config `sources`; later user choices win across random-port restarts.
    Missing or all-disabled sources produce an empty successful changeset.
16. Keep `cleanup-internal` Codex-only. Adding a read-only Claude adapter does not
    grant authority to delete any Claude-derived document.

### Windows atomic publication reliability

- Native Windows validation repeatedly exposed transient `Access is denied`
  failures on different existing metadata-migration tests while replacing a
  verified owned sidecar. Each isolated test immediately passed, indicating a
  short-lived antivirus/indexer handle rather than an identity failure.
- Added a Windows-only bounded retry around the final same-directory
  `os.Rename` used by `replaceOwnedFile`. It retries sharing/lock/access-denied
  errors for at most six attempts with 10–60 ms backoff. Unix remains a single
  rename, and persistent permissions, symlink, identity, or hash failures are
  not bypassed.

## Decisions and rationale

- **Read JSONL directly, but label the capability experimental:** `/export` is
  interactive and a scripted `--resume` request would invoke Claude, spend model
  usage, and append to native state. Direct stable reads are the only way to
  archive existing sessions without mutation, but the official format warning
  requires strict shape validation and fail-closed behavior.
- **Use the current ancestry, not raw file order:** rewind leaves alternate nodes
  in the same transcript. Mixing every historical branch into one Markdown file
  would misrepresent what the user currently sees. The last appended UUID leaf
  is the only deterministic current-branch signal supported by the observed
  data; omitted branch records remain in the untouched raw source and Git keeps
  previously exported current branches.
- **Do not export runtime attachment records:** observed `attachment` records are
  overwhelmingly hook results, reminders, queued commands, permissions, and
  other UI/runtime state. Direct user files are represented inside human message
  content blocks and provide the correct provenance boundary.
- **Group assistant fragments by message ID:** Claude stores one assistant API
  message across adjacent records. Grouping restores a readable assistant turn
  while excluding thinking and tool blocks. File-order grouping avoids relying
  on non-monotonic timestamps.
- **Prefer explicit names over generated titles:** this matches documented Claude
  picker behavior and preserves user intent. File mtime is not a trustworthy
  title timestamp.
- **Do not scan adjacent Claude stores:** prompt history, settings, auth state,
  session environment, file checkpoints, caches, and tool-result spills either
  contain secrets or are not direct conversation input. They are unnecessary for
  the requested Markdown transcript.
- **Retain existing schemas where their contracts already fit:** harness-qualified
  identity and required schema-v2 harness metadata already represent another
  adapter. Renderer v8 is the only global byte-format advance.
- **Peer switches avoid treating one harness as secondary:** all three native
  roots are optional. CLI discovery is automatic; GUI source choice is explicit,
  symmetric, locally remembered, and independent from archived/non-Git policy.

## Compatibility and migration

- Program version is `1.0.0`; renderer is v8 and session metadata schema v2
  accepts additive required harness value `claude-code`.
- Config advances from schema v1 to v2 with optional `sources`. V1 loads without
  mutation and migrates on the next authorized config write. Hosted/local
  repository schemas v1/v2, session metadata schema v2, attachment schema v1,
  layout v5, and export-result schema v3 remain unchanged.
- Existing Codex session keys and paths remain byte-for-byte compatible.
  DeepSeek session identity and paths remain unchanged.
- Claude directories always include a stable short variant to distinguish forks
  with copied time/title. This exception does not alter existing harness paths.
- A v0.7 binary will fail closed when it encounters a Claude schema-v2 sidecar
  with the unknown required harness value. It will not overwrite that entry.
- Existing owned Codex and DeepSeek documents will receive one verified renderer
  update the next time they are explicitly selected after renderer v8 ships.
- CLI and GUI request fields are additive and default false; existing invocations
  remain Codex-only.

## Known limitations and risks

- Anthropic explicitly does not promise a stable transcript-entry schema. Even
  well-tested shape-based parsing may need updates after any Claude Code release.
- Latest appended UUID leaf selection is an inference from current native data,
  not a documented public contract. Concurrently resuming one session in
  multiple terminals may create ambiguous branches; the adapter must warn or
  fail rather than merge unrelated leaves.
- Local evidence covers recent 2.1.205 through 2.1.235 transcript records, mostly
  created by the VS Code entrypoint. Older CLI-only formats need synthetic or
  reviewed fixtures before being claimed as supported.
- Claude Code deletes transcript sources after its configured retention period,
  30 days by default. Ordinary Session Manager export still retains previously
  published Markdown when the native source disappears.
- Text-backed document blocks preserve Claude's embedded representation, not
  necessarily the original file bytes. The export must label this honestly.
- Claude Desktop, Claude Code on the web before local resume, remote-only
  sessions, side-question threads, subagents, and cloud histories are not
  discovered.
- Tool output is intentionally omitted even though it may contain important
  debugging context. This matches the product's readable-conversation and secret
  minimization boundary, not lossless replay.
- Free text can still contain secrets not recognized by the redactor. Public Git
  publication continues to require human review.
