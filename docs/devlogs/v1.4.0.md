# Session Manager v1.4.0 Devlog

> Status: Released
> Date: 2026-09-30

## Objective and scope

Support metadata-first retrieval and verified bounded excerpts for CLI
workflows. Keep scoped export, custom output/source paths and evidence
provenance explicit. Do not change Markdown rendering or repair old hashes.

## Work completed

- Added `search` with case-insensitive AND query terms, repository name/remote/
  key/checkout, exact session/harness/device, overlapping source-activity
  intervals, timezone-aware date-only bounds, pagination and JSON.
- Default search reads metadata without conversation bodies. Unknown interval
  omissions are counted. Missing archives are errors, not empty success.
- Explicit `--content` requires a repository, session or bounded time window,
  refuses over 200 candidates, verifies document hashes and returns matching
  line numbers without dumping conversation text.
- Added `show` for exact session/key/path selection, optional harness/device
  disambiguation, full-document hash verification and numbered line excerpts.
  Responses are bounded to 500 lines/64 KiB and preserve snapshot coverage
  from verified frontmatter. User Markdown is not reparsed as native messages.
- Custom read paths are one-time overrides. Literal `~/...`, relative paths
  and spaces work; export `--output` stays one-time, `--directory` remembers.
  Explicit source-home/database and repository export paths are normalized.
- Added read/write/replacement guards without rewriting native data or exports.
- Embedded Go's IANA timezone database in the executable so date-only filters
  can use named timezones on machines without a system database or Go install.

## Decisions and rationale

- Reuse archive sidecars instead of adding a new database/catalog or native
  parser. Search candidates are not independent evidence of a completed task.
- Filter dates by source-activity overlap, including conversations created
  earlier; report missing times instead of inferring them.
- Hash verification stays exact. Modified documents remain inspectable as
  metadata but cannot silently become verified body evidence.
- Preserve numbered raw Markdown lines rather than inventing message splits
  from user-authored headings. Full source hash remains recorded provenance.

## Compatibility and migration

- Version advances to 1.4.0. New search/show JSON envelopes use schema v1.
- Existing list/export JSON, config v3, checkpoint v1, layout v5, sidecars and
  renderer v9 remain unchanged. No archive migration or hash normalization.
- Query commands do not write config, refresh sources, export or synchronize
  Git. Explicit export retains its existing publication and partial-error rules.

## Known limitations and risks

- Metadata search is linear in archive sidecars; no persisted index is added.
- Source activity end can include a title update and is a conservative
  candidate interval. Actual message coverage is `snapshot_through` from
  a verified document, not export time or the activity end.
- Legacy exports without a created timestamp require explicit unknown-time
  inclusion for date-filtered retrieval. Legacy documents without a document
  hash cannot be presented as verified excerpts.
- Document lines over the scanner's 4 MiB limit fail; selected lines over the
  64 KiB response bound require direct inspection of the verified local file.
- Original CRLF/hash mismatch behavior remains unchanged by request.
- Platform signing/runtime limits remain as recorded in v1.3.0.
