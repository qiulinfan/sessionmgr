# Session Manager v0.3.0-dev Devlog

> Status: Development
> Date: 2026-08-05

## Objective and scope

Reset Session Manager from a workspace/session migration system to a focused,
cross-platform Codex session exporter. The product remembers one user-selected
directory, exports sessions grouped strictly by hosted Git remote, and shows
only the changes created by the current operation. Both CLI and a local GUI are
provided by one pure-Go binary on macOS, Linux, and Windows.

## Work completed

### Product and command surface

- Reduced the data workflow to persistent configuration, Markdown export,
  derived listing, and version reporting.
- Added `config set-directory`, `config show`, `export`, `list`, `gui`, and
  `version`; retained `archive` and `--output` as compatibility aliases.
- Made no-argument launch open the GUI.
- Removed workspace capture/restore, verify, handoff, native resume, Store,
  push/pull, reconcile, initialization, doctor, SQLite, Capsule, encryption,
  and the prior Wails/React GUI.

### Persistent export directory

- Added schema-v1 JSON configuration under `os.UserConfigDir()` with a
  `SESSIONMGR_CONFIG` override for tests and portable use.
- Added directory creation, absolute-path normalization, directory validation,
  restrictive config permissions, `fsync`, and config-symlink refusal.
- Refused unknown config fields before write-back so newer data is not silently
  discarded by an older binary.
- Shared the same configuration store between CLI and GUI.
- Made `export --directory PATH` validate, use, and remember the directory.

### Repository and session identity

- Added transport-independent hosted Git remote normalization so SSH and HTTPS
  clones share a repository key without persisting credentials.
- Removed root-commit and local-path fallback identity: a session without a
  hosted remote is now skipped explicitly instead of being guessed into a key.
- Defined the archive as repository key -> session ID set -> immutable snapshot
  hash set.
- Made Codex `session_index.jsonl` the display-name source, with first-user-
  message and session-ID fallbacks.

### Markdown export and changesets

- Added discovery for active and archived Codex JSONL sessions.
- Added stable source reads and SHA-256 source/snapshot identities.
- Added readable user/assistant conversation rendering with deterministic
  frontmatter and semantic `<title>--<hash>.md` filenames.
- Added immutable, concurrent-safe publication using same-directory temporary
  files and no-replace hard links.
- Added per-operation `new`, `updated`, and `renamed` changesets.
- Changed human CLI output to display only current changes, or a single
  `No changes.` result; diagnostic counters remain in JSON.
- Kept latest-session and full-history listing as an explicit inspection
  command rather than part of normal export output.

### Cross-platform local GUI

- Added an embedded HTML/CSS/JavaScript interface served by the same Go binary.
- Added a responsive directory/configuration, export-scope, action, warning,
  and current-changeset UI.
- Added native directory picker adapters for macOS and Windows, with
  Zenity/KDialog/manual-path fallbacks on Linux.
- Added default-browser launch adapters for all three OS families.
- Bound the GUI to loopback only, generated a random 256-bit token per launch,
  required it on every API request, limited request bodies, and set restrictive
  browser security headers.
- Added `make cross-check` and six-binary `make dist` targets for macOS, Linux,
  and Windows AMD64/ARM64.

### Safety and dependencies

- Kept raw Codex JSONL read-only and outside the generated export.
- Excluded tool inputs/outputs, developer/system instructions, reasoning,
  machine paths, authentication data, and environment values from Markdown.
- Added explicit redaction for common tokens, private keys, credential URLs,
  secret assignments, and sensitive-looking metadata.
- Removed all external Go dependencies; the product uses only the standard
  library and runtime Git.
- Kept Git staging, commit, and push outside the application.

### Tests and documentation

- Added CLI configuration/export/list end-to-end coverage.
- Added repository normalization and strict hosted-remote tests.
- Added content update, title rename, idempotency, conflict, redaction,
  semantic-path, listing, raw-source preservation, and concurrent publication
  tests.
- Added GUI auth, configuration persistence, incremental export, security
  header, and loopback-listener tests.
- Rewrote README, PRD, and specification for the persistent-directory,
  changeset-only CLI/GUI product.

## Decisions and rationale

- **Git remains the sync layer:** code state and archive transport already have
  a mature content-addressed system; Session Manager only produces files.
- **One configured directory:** persistent destination removes repetitive flags
  while staying transparent and editable.
- **Hosted remote is the only repository key:** local paths and root commits do
  not express the user's intended cross-machine identity reliably enough.
- **Append-only snapshots:** updates and renames add files instead of mutating
  them, so multi-machine merges are set unions.
- **Changeset-only primary UI:** the useful answer after export is what changed
  now, not a repeated dump of everything already stored.
- **Native ID plus semantic title:** stable Codex ID provides membership while
  mutable title provides human meaning.
- **Local browser GUI instead of a WebView framework:** one standard-library
  binary can serve an equivalent experience across all three OS families
  without Node, CGO, platform SDKs, or a second dependency graph.
- **Loopback plus random token:** localhost alone is not an authentication
  boundary; the per-process token protects configuration and export actions.
- **No automatic Git mutation:** review, staging, committing, and pushing remain
  explicit user actions.

## Compatibility and migration

- This is an intentional breaking product reset from v0.1/v0.2.
- Removed commands: `init`, `doctor`, `capture`, `show`, `verify`, `restore`,
  `handoff`, `push`, `pull`, and `reconcile`.
- Old manifest, normalized-event, Store, Capsule, encryption, SQLite, operation
  report, and Wails GUI contracts are no longer read.
- Markdown repository/snapshot frontmatter and persistent config introduce
  schema version 1; rendering introduces renderer version 1.
- Existing `~/.sessionmgr` homes are not modified or deleted.
- The earlier v0.3 development command `archive --output PATH` remains accepted,
  but new workflows should configure a persistent directory and call `export`.
- Raw Codex JSONL remains in its native location and can coexist with old and
  new Session Manager data.

## Known limitations and risks

- Free-form user/assistant text may contain secrets not matched by finite
  redaction rules; generated Markdown requires review before publication.
- Tool arguments/results, developer/system messages, and reasoning are omitted,
  so Markdown is not a lossless replay format.
- Sessions without a hosted Git remote are skipped by design.
- Hosted services that treat path case as equivalent can still produce two keys
  because v1 preserves path case.
- Hard-link publication requires filesystem hard-link support; standard APFS,
  ext4, and NTFS support it, but removable/network filesystems may not.
- Linux native directory browsing requires Zenity or KDialog; manual path entry
  always remains available.
- The Codex JSONL format is not a public stable schema; unknown records remain
  counted but may not contribute readable content.
- The browser GUI is local, not a packaged native window; closing the browser
  tab does not stop the server process, which remains controlled by Ctrl-C.
- The script has not been run against the developer's real Codex home; tests
  and GUI validation use disposable fixtures only.
