# Session Manager v0.3.0-dev Devlog

> Status: Development
> Date: 2026-08-05

## Objective and scope

Reset Session Manager from a workspace/session migration system to a focused,
cross-platform Codex session exporter. The product remembers one user-selected
directory, exports sessions grouped strictly by hosted Git remote, and shows
only the changes created by the current operation. Both CLI and a local GUI are
provided by one pure-Go binary on macOS, Linux, and Windows.

## Requirements recorded before the active-session iteration

The following user requirements were recorded verbatim on 2026-08-05 before
implementation:

> - 导出的过程中, 正在进行的 session 的问题? 这些 sessions 是否会被锁? 如果被锁,
>   本次直接忽略这些 Sessions 就行
> - 另外, 我们是否可以获取 sessions 中每个对话的时间轴, 比如什么时候被创建,
>   什么时候是最后一次对话? 以及各个对话时间点; 如果有这些细节, 信息会更加完整

The implementation contract derived from that request is:

1. Session Manager must not block, modify, or require ownership of Codex's
   source files. A source that the operating system reports as locked or busy
   is ignored for the current export and remains eligible for the next export.
2. File locking is not a portable liveness signal: Unix locks are commonly
   advisory and an active session may be momentarily idle. The exporter will
   therefore observe all source fingerprints across one shared, short stability
   window, then verify the fingerprint again after reading.
3. A file that changes during the observation/read window, disappears during
   capture, is reported as locked by the operating system, or ends with an
   incomplete JSONL record is classified as `busy`. It creates no snapshot,
   warning, or non-zero exit status. JSON results retain a `busy` count so the
   ignored work remains observable without making normal active use an error.
4. Other failures remain `skipped` warnings and preserve the current partial-
   failure behavior; permission, parsing, identity, and publication failures
   must not be mislabeled as ordinary activity.
5. Timeline metadata must distinguish session creation, first rendered message,
   last rendered message, last source event, and title update. `updated_at` may
   remain the latest overall source/title change for ordering, but must not be
   presented as the last conversation time.
6. Every rendered user/assistant message retains its source timestamp and file
   order. Missing timestamps stay absent rather than being inferred from file
   metadata. The Markdown frontmatter adds explicit message counts and timeline
   fields so agents and humans can inspect the session without reparsing prose.
7. Because the Markdown contract changes, the renderer version must advance;
   existing immutable v1 files remain valid and are never rewritten.

Acceptance for this iteration requires locked/busy classification tests,
batch-window mutation coverage, no-error busy-only export behavior, precise
timeline parsing/rendering tests, normal and race test passes, and no-CGO builds
for macOS, Linux, and Windows.

## Requirements recorded for the semantic-layout iteration

The following user requirements were recorded verbatim on 2026-08-05:

> - 第一, hash value 不要直接放在文件夹上, 而是应该放在文件夹里一个单独的文件.
> - md 文档也是. 文件名里不要有那么多 hash! 一定要一眼明了.
> - 我想: 能不能用一个隐藏的 . 文件来表示呢?
> - hash value 能否由设备 + session 自己带的 hash value 表示呢?

The implementation contract derived from that request is:

1. Visible repository, device, session-directory, and Markdown names must be
   semantic. Hashes and native IDs must not be embedded in those names.
2. Each current session is represented by one `conversation.md`. Git history,
   rather than duplicate hash-named Markdown files, retains older revisions.
3. Repository identity is stored in `.sessionmgr-repository.json`; session,
   device, source, and rendered-document identity is stored in
   `.sessionmgr-session.json`. These hidden JSON files are versioned, strict,
   inspectable metadata rather than secret storage.
4. A persistent random device ID is created in the machine-local Session
   Manager config. A session key is derived from that device ID plus Codex's
   native session ID. The raw-source and rendered-document hashes remain
   separate because identity and change detection are different concerns.
5. The visible layout is
   `repositories/<host>/<owner>/<repo>/sessions/<device>/<created-time>--<title>/conversation.md`.
   Semantic-path collisions must be detected through the hidden identities and
   refused, never resolved by silently overwriting or appending a hash.
6. Re-export may replace only a document whose bytes still match the document
   hash recorded by Session Manager. A manually edited or conflicting file
   blocks that session and remains untouched. A title change may rename the
   semantic session directory only after the same ownership check.
7. The v1/v2 hash-named layout remains listable as legacy read-only data. The
   exporter does not delete or rewrite it automatically; cleanup requires an
   explicit, reviewable migration because existing archives may contain user
   changes.

Acceptance for this iteration requires deterministic device/session identity,
semantic-path and hidden-sidecar tests, content update and title-rename tests,
manual-edit and identity-collision refusal tests, legacy listing coverage,
normal and race tests, and no-CGO builds for supported platform families.

## Requirements recorded for the chat-attachment iteration

The following user requirements were recorded verbatim on 2026-08-05:

> - 除了 git 仓库本身的文件之外, 用户还可能会投喂其他文件. 这些文件我们有跟着一起导出的办法吗
> - 对, 就这样, 支持聊天框投入进去的文件即可, 单文件上限 50MiB (< git LFS)

The implementation contract derived from that request is:

1. Only files represented by structured user-chat input are in scope. Paths
   mentioned in prose, tool inputs/outputs, and files independently read by an
   agent are never inferred as attachments.
2. The exact per-file cap is 50 MiB (`50 * 1024 * 1024` bytes), inclusive.
   Oversize, busy, missing, or remote-only attachments do not fail the session;
   the conversation is exported with an inspectable attachment status and a
   warning, and unresolved local inputs remain eligible for a later retry.
3. Embedded session bytes are preferred. Legacy local paths are read only as
   regular non-symlink files with before/after stability checks. Remote URLs
   are not downloaded.
4. Copied bytes live in a readable `attachments/<sequence>-<name>` path. Hashes,
   sizes, MIME types, source classes, status, message position, and any Git
   proof live in the hidden session sidecar; absolute source paths and data
   URLs are not persisted.
5. A file is omitted as already covered by Git only when its bytes are proven
   identical to the tracked blob at the session's recorded commit and relative
   repository path. Merely residing inside a worktree is insufficient.
6. Attachment files become owned archive objects: an existing file must match
   the sidecar content hash before update/rename, and a modified file, symlink,
   or path collision must never be overwritten.
7. Known authentication databases, environment files, private keys, complete
   token patterns, and secret assignments are recorded as `blocked_sensitive`;
   their bytes and content hashes are not added to the archive.

Acceptance requires structured parser fixtures, exact-limit and over-limit
coverage, embedded/local/remote/Git classifications, attachment manifest and
Markdown-link checks, repeat/update/title-rename behavior, manual-edit and
symlink refusal, normal/race tests, and no-CGO builds.

5. Old layout-v3 repository sidecars and v1/v2 archives are not silently
   deleted. An interrupted per-session move remains recoverable by accepting a
   verified layout-v3 session sidecar under its newly published v4 repository.

Acceptance requires exact visible-path tests, nested namespace coverage,

coverage, normal/race tests, and no-CGO builds.

## Requirements recorded for the injected-context filtering iteration

The following user requirements were recorded verbatim on 2026-08-05:

> 我看到大量导出 sessions 是这种内容, 这些是什么
>
> 这些是不是应当去掉
>
> 好的, 请你修复这一问题

Inspection of one affected raw Codex source established that Codex Desktop had
written `recommended_plugins`, AGENTS instructions, and `environment_context`
as a `response_item.message` with `role=user`, followed by the actual prompt as
both another user response item and an `event_msg.user_message`. The current
parser incorrectly treated both response items as visible user turns and used
the injected one as the fallback title when `session_index.jsonl` had no entry.

The implementation contract derived from the request and that evidence is:

1. Raw Codex JSONL remains the archival source of truth and is never rewritten
   or deleted. Filtering applies only to the derived conversation and title.
2. When user-message events exist, `event_msg.user_message` is authoritative
   for visible user intent. Unmatched user-role response items are internal
   context and must not be rendered.
3. A response user item whose normalized text matches the user event may still
   supply richer structured attachment bytes. The event supplies identity,
   text, timestamp, and ordering; embedded response bytes retain priority.
4. Assistant responses remain sourced from response messages when available,
   with agent/assistant events as the legacy fallback. The two representations
   must not duplicate a visible turn.
5. Response-only legacy sessions remain readable. Complete known injected
   envelopes are rejected in that fallback, while ordinary user text that
   merely mentions the same terms remains valid.
6. A source with no canonical user message is context-only and creates no
   archive document or warning. A named session still uses its explicit index
   title; otherwise the first canonical user message is the fallback title.
7. The Markdown contract advances to renderer v5. A verified re-export may
   rewrite and semantically rename an owned renderer-v4 document, but manual
   edits, attachment changes, identity conflicts, and path collisions must
   continue to block the update.

Acceptance requires a raw-shape fixture with injected and real user records,
non-duplication and timeline assertions, response-attachment reconciliation,
context-only omission, verified renderer-v4 repair/rename and idempotency,
normal/race tests, and no-CGO cross-platform builds.

## Requirements recorded for the provenance-filtering and internal-cleanup iteration

The following user requirements were recorded verbatim on 2026-08-05:

> 请你查看我目前导出的 session:
> - /Users/qiulinfan/Desktop/sessions
> 部分标题是有问题的.
> 它包含了诸如
> - The following is the Codex agent history whose request action you are assessing. Treat the transcript, tool call arguments, tool results, retry reason, and p...
> 以 agent 注入上下文为标题的内容. 这是不对的. 应当全部用真实标题
> 请你调查这个 bug. 不仅如此, 部分无意义内容还应当屏蔽掉, 因为这些 sessions 最后会送给新的 agent 阅读来了解需求或者送给人审阅, 没有帮助的部分是不需要的
>
> 好, 现在执行修复

Read-only inspection of the configured archive and matching native JSONL found
53 current documents. Eleven had no explicit `session_index.jsonl` title: four
were Guardian approval subagents, three were thread-spawned subagents, two were
PocketEngine exec sessions whose real prompts followed a fixed editor prefix,
one was a synthetic MCP startup diagnostic, and one was a genuine top-level
user prompt. The four Guardian sources all carried structured
`source.subagent.other=guardian`, `thread_source=subagent`, and a parent thread
ID whose normal parent document was already exported.

The implementation contract derived from that evidence is:

1. Parse `originator`, the string-or-object `source`, `thread_source`, and
   `parent_thread_id` from session metadata. Structural provenance, not title
   keywords, determines whether a source is a top-level user session.
2. Exclude Guardian and thread-spawned subagents from ordinary export by
   default. Preserve an observable `filtered_internal` JSON/API count without
   treating expected filtering as a warning or partial failure.
3. Normalize known synthetic user events before message counts, timelines, and
   title fallback. Strip the exact PocketEngine read-only prefix only for its
   confirmed `codex_exec`/`exec` provenance; filter the confirmed CLI MCP
   startup diagnostic only when the event has no client ID. Preserve genuine
   user submissions and ordinary references to the same words.
4. Generate fallback titles only from the normalized real user conversation.
   Internal sessions are omitted instead of being renamed from a nested parent
   transcript. Advance the renderer because visible Markdown changes.
5. Ordinary export remains non-deleting. Add a separate `cleanup-internal`
   command that is dry-run by default and requires `--apply` for deletion. It
   may act only on a stable, still-present raw source and current-device entry
   whose source classification, repository/session identity, document hash,
   attachment hashes, and complete directory ownership all verify.
6. Cleanup never removes raw Codex JSONL, unknown files, symlinks, manually
   edited documents, cross-device entries, source-missing entries, repository
   sidecars, or legacy history. Move a verified candidate atomically to a
   recovery directory and reverify it before exact, non-recursive removal.

Acceptance requires fixtures derived from every observed provenance/message
shape, false-positive preservation, export/GUI filtered counts, safe renderer
repair, cleanup dry-run/apply/manual-edit tests, normal/race tests, no-CGO
cross-platform builds, a real-archive dry run, and post-migration idempotency.

## Decisions and rationale

- **Git remains the sync layer:** code state and archive transport already have
  a mature content-addressed system; Session Manager only produces files.
- **One configured directory:** persistent destination removes repetitive flags
  while staying transparent and editable.
- **Hosted remote is the only repository key:** local paths and root commits do
  not express the user's intended cross-machine identity reliably enough.
- **One semantic current document:** each device/session owns one readable
  `conversation.md`; Git already preserves its older revisions, so duplicate
  hash-named snapshot files add clutter without adding durable history.
- **Identity is hidden metadata, not a pathname:** device + native session ID
  establishes membership, while visible names remain meaningful and mutable.
  Source and document hashes retain their narrower change-detection and
  overwrite-protection roles.
- **Refuse semantic collisions:** adding hashes back to resolve a rare collision
  would violate the readable-layout goal. A collision is an explicit skipped
  source that requires the user to change a device/title name.
- **Changeset-only primary UI:** the useful answer after export is what changed
  now, not a repeated dump of everything already stored.
- **Native ID plus semantic title:** stable Codex ID provides membership while
  mutable title provides human meaning.
- **Local browser GUI instead of a WebView framework:** one standard-library
  binary can serve an equivalent experience across all three OS families
  without Node, CGO, platform SDKs, or a second dependency graph.
- **Loopback plus random token:** localhost alone is not an authentication
  boundary; the per-process token protects configuration and export actions.
- **No automatic Git mutation:** review, staging, committing, and pushing remain
  explicit user actions.
- **Observe rather than lock active sessions:** one batch quiet window plus
  identity checks is portable and non-invasive; advisory locks alone cannot
  establish whether a Codex session is active.
- **Conversation time is not generic update time:** creation, message activity,
  source activity, and title edits have separate meanings and are preserved as
  separate fields.
- **Structured user input is the attachment boundary:** only an explicit
  user-message attachment record is reliable evidence that the user intended a
  file to travel with the conversation. Text path guessing would capture tool
  work and unrelated machine files.
- **Embedded bytes outrank mutable paths:** current Codex rollout response items
  preserve local image/audio bytes as data URLs. Those bytes represent what was
  actually submitted; a legacy local path is only a best-effort fallback.
- **Attachment failures are partial by design:** a missing or oversize file
  should not erase a useful conversation export. The hidden status and warning
  make the gap inspectable and local unresolved inputs are retried.
- **50 MiB is a binary, inclusive cap:** the contract uses exactly
  `50 * 1024 * 1024` bytes, leaving ordinary Git-hosting headroom below common
  LFS thresholds while avoiding decimal/binary ambiguity.
- **Git omission requires byte proof:** path membership alone cannot show that
  a working-tree file matches the historical input. Both the recorded commit
  blob and attachment bytes must agree before a copy is omitted.
- **No layout bump for optional owned objects:** attachment schema v1 is an
  optional, backward-compatible addition to layout v3; renderer v4 makes the
  Markdown change explicit while old v3 sidecars remain readable. The later
  repository-root flattening is a separate persisted-path change and therefore
  advances the archive layout to v4.
- **Host and namespace stay visible together:** dropping the host entirely
  would make identically named GitHub/GitLab owners collide unnecessarily.
  `<host>-<namespace>` removes navigation depth while preserving useful origin
  semantics.
- **Layout migration reuses owned-file verification:** v3 documents are moved
  only through the same document/attachment hash checks used for an ordinary
  update. Old repository refs are retained instead of silently deleting
  potentially reviewed archive data.
- **Device is the meaningful repository child:** the device already partitions
  cross-machine sessions, so a literal `sessions/` directory adds navigation
  without adding identity or safety information.
- **Tree grouping stays in the browser:** the existing flat changeset remains
  useful to CLI and automation. Grouping by repository key and device name in
  the GUI avoids a JSON compatibility change.
- **Language preference is browser-local:** language is presentation state, not
  archive or machine identity. Keeping it out of the shared config preserves
  the config schema and lets each browser remember its own choice.
- **User events express user intent:** `role=user` is no longer sufficient in
  Codex Desktop's storage format because the application uses it for generated
  task context. A `user_message` event is the independent signal that the user
  actually submitted the turn.
- **Reconcile instead of discard response data:** response messages can retain
  embedded attachment bytes absent from the event representation. Text-matched
  enrichment preserves those bytes without allowing unmatched injected turns
  into the visible conversation.
- **Context-only sources are not conversations:** exporting a title and document
  for startup context alone adds noise and machine details without preserving
  user work. The native source remains untouched and eligible for a future
  parser if Codex adds a new user signal.
- **Session provenance outranks user-role labels:** Codex stores Guardian,
  thread-spawned, editor-mediated, and runtime-diagnostic inputs as user events.
  Structured `session_meta` source fields and client IDs distinguish those
  cases more reliably than role or title text; source-specific exact rules
  avoid broad heuristics that could delete a user's literal report.
- **Internal cleanup is explicit and source-backed:** ordinary export remains
  append/update-only. Removing a known bad derived document requires a separate
  dry-run-first command, a still-present raw source proving the classification,
  current-device identity, and complete owned-tree checksum verification.
- **Archive is not a mirror:** Codex can archive, compact, or remove native
  session files independently. Source absence cannot safely distinguish user
  intent from local retention policy, so Session Manager never derives a
  deletion from it.
- **Dark is the product default:** a single GitHub Dark-style palette keeps this
  small local tool visually consistent without adding OS-theme detection or a
  cross-device UI-preference format.
- **Make owns build environment selection:** target-specific exported Make
  variables work with both `cmd.exe` and POSIX shells and avoid mutating the
  developer's persistent Go environment. Race testing intentionally retains
  Go's native CGO setting because supported race builds require CGO.
- **Bootstrap is local and fail-closed:** silently invoking a system package
  manager would require administrator authority and mutate the developer's
  machine. The build instead downloads only the configured official archive,
  verifies its pinned checksum, and publishes it under `.tools/go/<os>-<arch>`
  only after complete extraction. Existing mismatched destinations and invalid
  cached archives are refused rather than overwritten.

## Compatibility and migration

- This is an intentional breaking product reset from v0.1/v0.2.
- Removed commands: `init`, `doctor`, `capture`, `show`, `verify`, `restore`,
  `handoff`, `push`, `pull`, and `reconcile`.
- Old manifest, normalized-event, Store, Capsule, encryption, SQLite, operation
  report, and Wails GUI contracts are no longer read.
- Markdown repository/snapshot frontmatter and persistent config introduce
  schema version 1; the timeline iteration advances rendering from version 1
  to version 2 without rewriting existing snapshots. The semantic iteration
  introduces layout/renderer v3 and optional device config fields while keeping
  the config schema backward compatible.
- Layout v3 creates semantic current documents beside, not on top of, v1/v2
  hash-named data. `list --history` keeps legacy files inspectable; no automatic
  deletion or migration is performed.
- Existing `~/.sessionmgr` homes are not modified or deleted.
- The earlier v0.3 development command `archive --output PATH` remains accepted,
  but new workflows should configure a persistent directory and call `export`.
- Raw Codex JSONL remains in its native location and can coexist with old and
  new Session Manager data.
- Renderer v4 keeps layout v3 and adds attachment schema v1 as optional sidecar
  data. Existing layout-v3 sidecars without attachment fields remain readable
  and are upgraded only by an ordinary verified export.
- Layout v4 changes only the visible repository root. Layout-v3 sidecars remain
  readable and migrate per session after ownership verification; repository,
  session, attachment, and renderer schemas otherwise remain compatible.
- Layout v5 removes only the `sessions/` path component below a v4 repository.
  Layout-v3/v4 sessions remain readable and migrate per session after ownership
  verification. The layout-v4 repository sidecar upgrades in place only when
  its full identity matches; that layout-only iteration did not change schemas
  or the renderer.
- Renderer v5 changes canonical message selection without changing layout,
  identity, attachment, or config schemas. Renderer-v4 sidecars remain readable;
  the next export verifies the current document and attachments before rewriting
  content or renaming a polluted semantic title directory. Unaffected documents
  also receive a one-time renderer update, after which export is again a no-op.
- Renderer v6 adds provenance-aware session and user-event selection without
  changing layout, identity, attachment, or config schemas. Renderer-v4/v5
  sidecars remain readable. Ordinary export updates and safely renames retained
  owned documents but does not delete newly excluded internal entries; those
  require the separate dry-run-first cleanup command.
- The dark palette and explicit missing-source retention rule change no persisted
  schema or API. Existing archives need no migration; active-to-archived movement
  and later source disappearance leave their stored bytes untouched.
- Build bootstrap adds no product schema or runtime migration. Existing system
  Go installations remain preferred when they meet the Go 1.24 minimum;
  generated `.tools/` content is local, ignored, and partitioned by host OS and
  architecture.

## Known limitations and risks

- Free-form user/assistant text may contain secrets not matched by finite
  redaction rules; generated Markdown requires review before publication.
- Tool arguments/results, developer/system messages, and reasoning are omitted,
  so Markdown is not a lossless replay format.
- Sessions without a hosted Git remote are skipped by design.
- Hosted services that treat path case as equivalent can still produce two keys
  because v1 preserves path case.
- No-replace first publication uses hard links; standard APFS, ext4, and NTFS
  support them, but removable/network filesystems may not.
- Linux native directory browsing requires Zenity or KDialog; manual path entry
  always remains available.
- The Codex JSONL format is not a public stable schema; unknown records remain
  counted but may not contribute readable content.
- Current public Codex input types guarantee structured image/audio inputs, not
  a generic `LocalFile` variant. Generic `input_file`/`attachments` parsing is
  compatibility-oriented; a client that persists a dropped file only as prose
  cannot be recovered without violating the no-path-guessing requirement.
- Secret detection is deliberately conservative but finite. Binary files with
  an innocuous name may still contain credentials, so copied attachments need
  the same private review as generated Markdown before public Git publication.
- A Unix process can hold an advisory lock that ordinary reads do not observe;
  the stability window detects writes, not an otherwise idle process's intent
  to write again later. Such a session may produce an intermediate current
  document and a later update; only commits made between them retain that state
  in Git history.
- Two sessions from the same device with the same normalized title and exact
  creation timestamp collide semantically. The second is deliberately skipped
  instead of gaining an opaque suffix.
- Layout v3 does not automatically remove development-era v1/v2 files, because
  they may have been reviewed or manually edited outside Session Manager.
- After all sessions from a layout-v3 repository have moved, its verified old
  repository sidecar and non-session parent directories remain until an
  explicit cleanup is designed. Empty legacy device/`sessions` wrappers are
  now removed after a successful verified move, but no non-empty directory is
  deleted as a side effect of export.
- Backend diagnostic and filesystem error strings remain in their original
  English form; the bilingual dictionary covers the full product UI and normal
  dynamic states, not arbitrary operating-system text.
- Response-only legacy data has no independent user-event signal. The fallback
  rejects the complete injected envelopes observed in current Codex Desktop,
  but a future unknown synthetic envelope in a truly response-only format may
  require another parser fixture; modern sources with user events do not depend
  on this envelope recognition.
- Internal cleanup deliberately requires a still-present, stable raw source and
  the current machine's device identity. It will not clean an old polluted
  document whose source has disappeared or whose device config was lost,
  because title heuristics alone are insufficient deletion authority.
- PocketEngine and MCP normalization is limited to the exact provenance and
  message forms observed in the real fixtures. New clients or wording require
  another evidence-backed fixture rather than a broad prefix rule.
- The current GUI is intentionally dark-only. It does not follow the operating
  system theme or expose a light-theme toggle.
- The browser GUI is local, not a packaged native window; closing the browser
  tab does not stop the server process, which remains controlled by Ctrl-C.
- The parser and cleanup command were run against the developer's real Codex
  home and configured archive for this iteration. The GUI acceptance tests and
  destructive-safety fixtures remain disposable; no remote publication was
  attempted.
- Windows race verification requires a CGO-capable C compiler in addition to
  Go. The temporary Windows validation toolchain had no compiler, so the
  native Windows race path was not verified. The same final source passed
  `go test -race ./...` with CGO and GCC under Ubuntu 24.04 WSL.
- Automatic Go bootstrap still requires a small platform launcher surface:
  PowerShell on Windows, or a POSIX shell plus `curl`/`wget`, `tar`, and a
  SHA-256 utility on macOS/Linux. It intentionally does not install Git, GNU
  Make, or a C compiler. The first bootstrap requires network access and roughly
  65–75 MB for the compressed Go archive per host platform.

## Next steps

1. Review the configured archive's existing dirty Git worktree before any
   archive commit. Keep the eight derived removals and renderer-v6 migration
   separate from unrelated pre-existing layout deletions where practical.
2. Design an explicit dry-run-first migration command if development-era v1/v2
   archives need cleanup; do not make deletion part of ordinary export.
3. Consider a supported `config set-device-name` command instead of requiring
   manual config editing when a hostname is not a useful display name.
4. Add signed/notarized installers only after the command and storage schema
   stabilize.
5. Consider an explicit in-page “stop server” control if users prefer it over
   terminal lifecycle management.
6. Exercise image, audio, and generic-file inputs from each supported Codex
   client in a private disposable archive as those client schemas evolve.
7. Consider an explicit verified cleanup/migration for orphaned attachment
   objects only if a future Codex format can remove attachments from an
   existing append-only session; ordinary export intentionally performs no
   deletion.
8. Add a parser fixture whenever Codex introduces a new user-intent event or a
   response-only injected envelope; do not broaden text heuristics without raw
   source evidence.
9. Add a light or system-following theme only if users request it; keep the
   GitHub Dark palette as the deterministic default.
10. Consider an opt-in `--include-subagents` or a parent-linked distilled
    subagent summary only if users later need delegated detail; keep standalone
    internal sessions excluded by default.
