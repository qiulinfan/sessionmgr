# Session Manager v1.1.0 Devlog

> Status: Released
> Date: 2026-09-29

## Objective and scope

Export Oh My Pi and OpenCode conversations beside Codex, Claude Code, and
DeepSeek Harness. Detect the five supported sources independently and enable
each by default, with explicit CLI and GUI selection. Preserve the native
sources and the ownership checks on the existing Markdown archive.

This version does not import a transcript into another harness, infer a
deleted workspace from a path slug, or add a generic unknown-harness scanner.

## Work completed

### Session sources

- Added OMP JSONL v3 discovery and current-parent-chain rendering. The fixed
  title slot, branch alternatives, tool calls, and blob image references are
  handled separately from user/assistant text.
- Added OpenCode session/message/part reading through one read-only SQLite
  transaction. Child sessions are internal; reasoning and tool output are not
  rendered. An assistant message without a native completion time is held for
  the next export while the prior completed prefix remains available. A
  per-session hash covers the ordered rows without copying the database, WAL,
  auth, or share tables.
- Added harness-qualified session keys and distinct visible directories for
  both sources; existing Codex/Claude/DeepSeek identity and paths are retained.
- Added completed-turn projection for active sources: Codex `task_complete`,
  Claude `end_turn`/`stop_sequence` on the selected ancestry, OMP `stop` on
  the selected parent chain, DeepSeek `turn/end`, and OpenCode assistant
  `time.completed`. A new unfinished turn keeps the preceding completed
  conversation and does not change its source hash. A half-written final
  JSONL line is ignored only when the completed prefix can be verified.
- Excluded Claude Code cloud transcripts copied into the local project tree
  when they carry `teleported-from` or a recognized cloud
  entrypoint. A local transcript with the same native ID still exports.

### Source selection and interface

- Added OMP and OpenCode to CLI flags, local environment detection, GUI
  switches, and English/Chinese status text. CLI `--sources` selects a named
  subset; otherwise a saved choice or all five supported sources applies.
- Removed the library's implicit Codex selection. A library caller with no
  `Sources` value selects only explicitly supplied source paths, preventing
  test fixtures from falling into unrelated native user homes.
- Advanced local config to schema v3. Reading v2 preserves its three choices
  and enables the two new sources; first-time GUI selection enables all five.

## Decisions and rationale

- **Use read-only SQLite for OpenCode:** its installed `opencode export`
  command returned exactly 65,536 bytes and invalid JSON for an isolated
  session larger than that. `modernc.org/sqlite v1.46.0` is pure Go, supports
  the repo's Go 1.24 minimum, and keeps `CGO_ENABLED=0` portable builds.
- **Treat Codex identity as historical compatibility only:** existing Codex
  sidecars without a harness and old session keys keep their established
  meaning. New source selection gives Codex no priority or fallback status.
- **Keep workspace mapping evidence-based:** a native OpenCode session whose
  recorded directory has disappeared remains skipped, even with non-Git
  inclusion. The product does not synthesize a new directory identity.
- **Use native end markers rather than elapsed time:** an idle or slow agent
  can still be mid-turn. End markers keep partial assistant text and tool
  output out of the completed Markdown. Branch-aware Claude and OMP readers
  never use a completed answer from an abandoned branch. OpenCode's
  `time.completed` on a `finish=tool-calls` assistant settles that message,
  but the user turn remains open.
- **Hash only completed content:** OpenCode omits its mutable
  `session.time_updated` from the row hash; DeepSeek hashes decoded JSONL,
  including for Zstandard sources. This makes a completed source and its
  subsequent active prefix compare equal. Post-turn title/status records
  before the new turn remain in the prefix.

## Compatibility and migration

- Source version advances from 1.0.2 to 1.1.0. Config schema advances
  from v2 to v3; v1/v2 read-only loads normalize in memory, and the next
  config write persists v3.
- CLI adds `--sources`, `--omp-home`, `--omp-session-dir`, and `--opencode-db`. CLI default export
  now follows saved source preferences when present; otherwise all supported
  sources are enabled. GUI adds two source switches and environment rows.
- Repository schema, session metadata schema v2, attachment schema v1,
  layout v5, renderer v9, and export-result schema v3 remain unchanged.
  Required sidecar harness values add `omp` and `opencode`; earlier readers
  reject those unknown values rather than overwrite them.
- OMP v3 JSONL and the observed OpenCode SQLite session/message/part schema
  are supported. Unknown OMP header versions and unsupported OpenCode schema
  changes fail closed.
- The archive schema and renderer are unchanged. A previously archived
  compressed DeepSeek source or OpenCode source may receive one source-hash
  update on its next export because their hash inputs now use decoded JSONL
  and omit mutable `session.time_updated`, respectively. Native sources are
  never rewritten.

## Known limitations and risks

- OpenCode sessions with a missing native CWD cannot be mapped to a Git or
  device-local directory. The current local session demonstrates this case.
- OpenCode non-data-URL file references and OMP non-blob image references are
  reported as unarchived references. Native resume, branch switching, and
  full reasoning/tool transcript replay are outside this Markdown exporter.
- The default OMP detector follows the normal agent home or
  `PI_CODING_AGENT_DIR`; `PI_CODING_AGENT_SESSION_DIR` and
  `--omp-session-dir` cover independently placed session files. Named profiles
  and Orca-managed overlays not selected in the Session Manager environment
  still need their actual home/session directory passed explicitly.
- Windows runtime behavior against a real OpenCode database still needs a
  Windows host; cross-builds alone verify compilation and packaging, not
  live Windows application integration.
- Claude cloud copies without any recognizable provenance marker cannot be
  distinguished from native local JSONL by this private, unstable transcript
  format. The fixture verifies known teleport/cloud markers; no live cloud
  transcript was available to test. Markerless legacy file formats retain
  their prior projection behavior because they do not record a reliable turn
  completion boundary.
- A file that changes identity, size, or mtime during the 350 ms observation
  window remains `busy` for that invocation; an incomplete compressed
  Zstandard frame is also `busy` until its checksum can be verified.

## Next steps
