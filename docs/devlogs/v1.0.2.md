# Session Manager v1.0.2 Devlog

> Status: Released
> Date: 2026-09-04

## Objective and scope

Recover valid Codex and Claude Code conversations that v1.0.1 incorrectly
skips when their native storage contains normal continuation fragments, copied
fork ancestry, detached runtime roots, or replayed UUID records. Preserve raw
native sources as read-only truth and retain fail-closed behavior for ambiguous
current conversation paths or conflicting identities.

This version does not alter released v1.0.0/v1.0.1 tags, import native sessions,
guess a deleted workspace path, export tool traces, or delete archive entries.

## Work completed

### Codex fragment coalescing

- Added a parse-before-publish phase so multiple physical Codex JSONL files with
  one native session ID are grouped before publication.
- Validated a fragment group has one stable hosted remote or local workspace
  identity, sorted fragments by reliable message time plus raw-hash tie-break,
  and failed closed on an overlap, missing timing boundary, or identity conflict.
- Merged verified fragments into one logical session: earliest creation time,
  ordered messages, summed counters, latest available hints, and a domain-
  separated bundle source hash over the ordered raw fragment hashes.
- Replaced stale in-memory history entries after a successful publication rather
  than appending an obsolete pre-rename path. `publishSnapshot` also discards a
  missing history candidate and safely re-evaluates remaining owned candidates.

### Claude Code lineage recovery

- Kept `projects/*/<filename>.jsonl` filename stem as the Claude archive
  identity, while accepting foreign `record.sessionId` nodes as copied fork
  ancestry.
- Changed current conversation selection to the source-order last user/assistant
  node that belongs to the filename session ID. Attachments after that anchor,
  stale `last-prompt` metadata, and detached system roots no longer misidentify
  the current conversation.
- Resolved parent UUIDs relative to source order: use the latest prior
  occurrence, or one unambiguous forward occurrence. Only the selected ancestry
  is required to be complete and acyclic.
- Accepted replayed UUIDs only when their visible semantic projection is equal;
  differing type, timestamp, role, message ID, or content still blocks export.
  Off-ancestry replay and detached roots no longer block a valid current chain.
- Silently ignored bridge-only JSONL files without a filename-owned conversation
  anchor. Added a collision gate: two non-identical visible Claude transcripts
  with the same filename session ID across project directories are skipped as an
  ambiguity rather than overwriting each other.
- Advanced renderer to v9 to explicitly version the changed fragment and
  ancestry projection, following the existing parser/renderer version contract.

### Workspace privacy and publication safety

- Tracked selected-ancestry workspace candidates only in memory and retried
  repository mapping from the newest accessible selected path backward. A stale
  VS Code extension path can no longer override an accessible ancestor CWD.
- Replaced CWD-derived OS error text in export warnings with a generic workspace
  status, preventing absolute paths from reaching CLI JSON or the GUI response.

### Investigation evidence

- Read-only inspection found the reported Codex native ID in three continuous
  physical fragments; its prior sidecar represented only the middle fragment.
- Read-only inspection of 62 direct Claude transcript files found 61 UUID graphs
  with valid selected ancestry, including copied session IDs, detached system
  roots, and replayed UUIDs that the prior global validation rejected.

## Decisions and rationale

- **Coalesce Codex before publish:** correcting only stale history would stop
  the ENOENT but keep overwriting the archive with the final physical fragment.
  Bundling preserves the complete conversation and makes any fragment mutation
  observable through one deterministic source hash.
- **Use filename-owned Claude conversation anchors:** Claude fork transcripts
  retain ancestor records with their original IDs. Treating every record ID as
  the file identity loses valid descendants; using the filename remains stable
  for existing archive keys.
- **Validate the selected chain, not stale graph debris:** Claude can retain
  detached runtime roots and replay metadata. Those records have no authority to
  invalidate a separately provable current user/assistant ancestry.
- **Do not guess cross-project Claude identity:** schema v2 does not encode
  Claude project-key provenance. Until a future schema migration, visible,
  non-identical same-filename sources are rejected rather than silently merged.
- **Do not guess a deleted CWD:** only selected-chain paths that still exist are
  candidates for Git or local-directory mapping; project directory slugs are
  never reversed into an absolute path.

## Compatibility and migration

- Program version advances from `1.0.1` to `1.0.2`.
- Config, repository, session metadata, attachment, layout, CLI JSON,
  and GUI API schemas remain unchanged.
- Renderer advances from v8 to v9. Existing selected documents receive one
  ownership/hash-verified renderer update on their next export.
- Existing single-file Codex sessions retain their source hash and archive path.
  A newly coalesced multi-fragment Codex session uses a bundle source hash, so
  its next verified export updates the document once with the full transcript.
- Existing Claude archive identity remains device + `claude-code` + filename
  session ID. The new cross-project ambiguity gate fails closed rather than
  migrating the key; a project-key-aware schema version is deferred.

## Known limitations and risks

- Claude Code documents its JSONL entry format as internal and subject to change.
- A fragment merge fails closed on repository identity conflict, overlap, or
  unsafe ordering rather than choosing a partial transcript.
- Same filename session IDs in separate Claude project keys cannot be faithfully
  distinguished by schema v2. v1.0.2 rejects non-identical visible copies; a
  future schema-major identity change is needed for independent export.
- A transcript whose entire selected ancestry has inaccessible CWDs remains
  skipped; the exporter does not derive a path from a project slug.
- The legacy capture/push/pull/restore end-to-end test no longer exists in this
  Markdown-exporter source tree. Archive integration tests and disposable
  native-source exports provide the applicable end-to-end evidence above.
