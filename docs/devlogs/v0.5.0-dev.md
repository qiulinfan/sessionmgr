# Session Manager v0.5.0-dev Devlog

> Status: Development
> Date: 2026-08-05

## Objective and scope

Allow users to explicitly include Codex sessions whose working directory has no
hosted Git remote. The CLI and local GUI expose an opt-in switch, and selected
local directories use a deliberately coarse full-export policy while retaining
the same provenance filtering, redaction, attachment, ownership, and
append/update-only safety boundaries as hosted Git sessions.

This version does not add Git mutation, cross-device identity for arbitrary
local directories, native Codex resume, mirror deletion, or automatic pruning.

## Work completed

### Local-directory identity and layout

- Added a hashed local directory ID and a device-scoped repository key derived
  from that ID plus the configured device ID, allowing sidecar validation
  without persisting the normalized absolute CWD.
- Kept the absolute CWD out of Markdown, repository metadata, session metadata,
  human output, and JSON changesets.
- Finalized the visible `(non-git)<device>/<directory>/<session>` layout. The
  device-scoped root carries the device name once, so local sessions no longer
  repeat a second device directory below the local directory identity.
- Kept the earlier v0.5 development draft
  `non-git-<device>/<directory>/<device>/<session>` readable. A selected full
  export migrates verified owned sessions to the final path and removes the old
  root only when its canonical repository sidecar is the sole remaining file.
- Added strict local-directory repository metadata schema v2 while continuing
  to read hosted repository schema v1 unchanged.

### Full export behavior

- Kept hosted Git export incremental and idempotent.
- Made an opted-in local-directory session pass through parsing, filtering,
  attachment handling, rendering, owned-file verification, and sidecar-last
  publication on every selected export.
- Added `full` changes after the initial `new` publication and exposed
  `filtered_non_git` and `full_exported` in export result schema v2.
- Kept source absence non-destructive: full export is not mirror reconciliation
  and never turns an omitted source into a tombstone.

### CLI and local GUI

- Advanced the program version to `0.5.0-dev`.
- Added CLI `export --include-non-git`, including support for targeting a
  non-Git directory with `--repo PATH`.
- Added optional GUI API field `include_non_git` and a bilingual unchecked
  checkbox that explicitly labels the operation as a full export.
- Added an English/Chinese `FULL` change badge and local-directory grouping in
  the existing change tree.
- Kept hosted Git changes grouped under device folders while rendering non-Git
  session cards directly below their device-scoped repository root. This
  prevents a local session path from being mistaken for a device folder.

### Tests and documentation

- Added archive coverage for default exclusion, full repeat publication,
  schema-v2 sidecar privacy, device-scoped identity, structural subagent
  filtering, semantic layout, and manual-edit refusal.
- Added CLI and GUI/API regressions for explicit inclusion and repeated full
  export, including GUI current-directory targeting.
- Updated README, PRD, SPEC, program version, and the devlog index for v0.5.

## Decisions and rationale

- **Opt-in preserves v0.4 behavior:** hosted Git sessions remain the default;
  local directories are included only for the current CLI or GUI operation.
- **Local identity is intentionally device-scoped:** an absolute path has no
  truthful cross-machine meaning. Combining it with device ID prevents the tool
  from claiming two unrelated directories are one repository.
- **Paths are hashed, not archived:** absolute CWD is required to distinguish
  local directories on one machine but is unnecessary and privacy-sensitive in
  the shared archive.
- **Full export does not manufacture Git diffs:** local owned files are
  republished and reported as `full`, but no current-time field is injected when
  rendered bytes are otherwise unchanged.
- **Safety policy is shared:** local sessions are filtered before repository
  assignment and use the same document, attachment, symlink, collision, and
  source-retention checks as hosted sessions.
- **A new repository schema is explicit:** hosted schema v1 cannot honestly
  represent a repository without a canonical remote. Local schema v2 records
  the required kind and device ownership without weakening v1 validation.
- **Device scope appears once:** hosted repositories need a child device layer,
  but a local repository key and `(non-git)<device>` root are already device-
  scoped. Repeating the device below the directory adds navigation without
  identity information; parentheses keep the special root visually explicit.

## Compatibility and migration

- Program version advances from `0.4.0-dev` to `0.5.0-dev`.
- Existing hosted repository metadata schema v1, session metadata schema v1,
  layout v5, renderer v6, attachment schema v1, and config schema v1 are not
  rewritten or migrated.
- Local-directory repository metadata is introduced as schema v2. A v0.4
  binary fails closed when it encounters such a sidecar; v0.5 reads both hosted
  v1 and local v2.
- The final v0.5 local path replaces the earlier development draft without a
  schema/layout-number change because v0.5 remains unreleased. The reader keeps
  draft compatibility and export performs an ownership-verified per-session
  move; unowned or modified leftovers are never deleted.
- Export CLI/GUI JSON advances from schema v1 to v2, adding
  `filtered_non_git`, `full_exported`, and change kind `full`.
- `include_non_git` is an additive GUI request field whose omitted value is
  false. CLI automation must add `--include-non-git` explicitly.

## Known limitations and risks

- Local directory identity is not portable across devices, even when two
  machines happen to use the same absolute path.
- Two local directories whose device/directory display components normalize to
  the same visible path are refused rather than given an opaque suffix.
- A local-only Git worktree is treated as a local directory; its attachments are
  copied unless hosted-repository Git proof is available.
- The developer's currently present Codex sources did not include a real
  non-Git fixture, so native-client local-directory shapes remain verified by
  schema-realistic disposable fixtures rather than a live source.
- Older v0.4 binaries cannot list an archive after local schema-v2 repository
  metadata is added; use v0.5 or newer for that archive.
