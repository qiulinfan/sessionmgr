# Session Manager v1.4.3 Devlog

> Status: Released
> Date: 2026-10-11

## Objective and scope

Export active Codex Desktop sidebar conversations without scanning or archiving
CLI benchmark runs, subagents, archived roots or other harnesses in that scope.

## Work completed

- `smg export --sidebar-only` reads the newest native `state_N.sqlite` read-only
  and selects `source=vscode`, `archived=0` identities before parsing JSONL.
  Legacy Desktop entries without originator metadata remain eligible.
- Sidebar selection forces the Codex source and refuses include-archived.
  An absent or unsupported inventory fails before archive creation.
- WebUI defaults to the sidebar checkbox. Source controls and archived inclusion
  are disabled in that scope; users can uncheck it to select other sources.
- The checkpoint key includes sidebar selection without changing existing broad
  scope keys. Newly eligible threads are scanned independently of broad exports.
- Export JSON schema 6 adds explicit `scope=codex-sidebar` for scoped runs.
- The companion private backup helper invokes this native scope and requires its
  schema/scope receipt, retaining its own identity gate before Git staging.

## Decisions and rationale

Sidebar identity comes from native root-thread metadata, not titles, directory
names or the number of recent items returned by a limited UI listing. The SQLite
snapshot is never copied to the archive. All other export modes remain available
through explicit CLI/source choices. The GUI defaults serve the owner's backup
policy; no existing archive is deleted as a side effect of exporting.

## Compatibility and migration

CLI broad export behavior is preserved unless `--sidebar-only` is supplied.
The HTTP export request adds optional `sidebar_only`; omitted/false retains the
existing API behavior. WebUI starts with sidebar selection enabled. Strict
receipt consumers must accept schema 6; the scheduled helper now requires
smg 1.4.3 and verifies the sidebar scope explicitly. Existing checkpoint and
archive formats are unchanged; sidebar scans use an independent checkpoint.

## Known limitations and risks

- This inventory covers the local Codex home. A remote/cloud sidebar entry whose
  native source is unavailable locally cannot be collected by this mode.
- Native database schemas can change; unsupported schemas fail closed instead
  of falling back to all local sources.
- Export does not perform Git backup, remove older exports or rewrite history.
- Native Windows runtime execution remains delegated to the release workflow.
