# Session Manager v1.3.0 Devlog

> Status: Released
> Date: 2026-09-30

## Objective and scope

Expose the existing CLI as installed `smg`, open the native macOS app from the
terminal, and publish standalone CLI downloads. Archive formats are unchanged.

## Work completed

- `make build` creates `bin/sessionmgr` and `bin/smg` from one entrypoint.
- Added `install-cli [--directory PATH]`, defaulting to `~/.local/bin/smg`
  (`smg.exe` on Windows). Copy/fsync/rename preserves the executable; Go build
  identity checks prevent overwriting unrelated commands or symlinks.
- Bare invocation/`open` prefer a verified native app in user/system
  Applications on macOS. `gui` explicitly starts the browser server.
- The macOS app menu can install the bundled CLI without Go or a checkout.
- Added macOS universal and Linux AMD64/ARM64 CLI tarballs and checksums.
  Publication now waits for Windows, macOS and Linux builds.

## Decisions and rationale

- Copy one real executable rather than depending on a shell alias, source
  checkout or mutable app path. CLI/GUI share config and incremental state.
- Read build identity without executing an unknown existing command.
- Keep installation user-local; report absent PATH membership without editing
  shell profiles or installing a service.

## Compatibility and migration

- Version advances to 1.3.0. Existing `sessionmgr` remains an alias; all its
  subcommands still work. Bare macOS invocation prefers the installed App;
  `gui` retains explicit foreground browser behavior.
- Config v3, checkpoint v1, export result v4, layout v5, session metadata v2,
  and renderer v9 stay unchanged. No session/document migration.

## Known limitations and risks

- Installer does not configure PATH; its result explains missing membership.
- Windows can refuse updating a running destination executable. The existing
  file is preserved and the error asks the user to close it.
- macOS remains ad-hoc signed without Developer ID/notarization; Windows
  signatures remain as documented in v1.2.0.
- Live CLI installation/native UI is checked on macOS. Cross-builds and CI do
  not constitute a live Linux/Windows desktop UI test.
