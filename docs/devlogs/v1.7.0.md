# Session Manager v1.7.0 Devlog

> Status: Development
> Date: 2026-10-24

## Objective and scope

GUI-only export also archives the Oh My Pi and Claude Agent conversations that
the owner started in Zed's Agent panel over ACP, while OMP runs from the CLI and
other Claude Agent SDK programs, which are automation, stay out of it. It also
makes Session Manager pass its tests and export on native Windows. Changing
OMP or Zed and the Session Manager UI are outside this version.

## Work completed

### Export

- `Options.OMPGUISessionDir` and `export --omp-gui-session-dir` name the OMP
  session directory written by GUI clients; the default is
  `<omp-home>/sessions-gui` (`internal/archive/omp.go`, `internal/app/app.go`).
- GUI-only export no longer drops the OMP source. It reads only the GUI
  directory; a missing directory yields zero candidates, as before
  (`internal/archive/archive.go`).
- `Options.ZedDB` and `export --zed-db` name Zed's workspace database
  (default: the stable channel's `db/0-stable/db.sqlite` in Zed's data
  directory). GUI-only export reads the `session_id` of unarchived
  `sidebar_threads` rows whose `agent_id` is `claude-acp` and also accepts
  Claude transcripts with the `sdk-ts` entrypoint whose ID is listed there
  (`internal/archive/zed.go`, `internal/archive/claude_desktop.go`). A missing
  database means Zed is not installed and adds nothing; an unreadable one fails
  the export.
- `--omp-gui-session-dir` now resolves `~` like the other path flags.

### Windows

- Every SQLite database (Codex's sidebar `state_*.sqlite`, OpenCode, the
  OpenCode GUI list and Zed) opens through `readOnlySQLiteURI`
  (`internal/archive/sqlite.go`). A Windows drive path became
  `file://C:/...`, which SQLite reads as the authority `C:` and refuses with
  `SQL logic error: out of memory (1)`; the URI is now `file:///C:/...`.
  The v1.6.0 sources fail the same tests on Windows; release CI runs tests on
  Linux only, so this went unnoticed.
- Export writes `<output>/.gitattributes` with `* -text` when the archive has
  none (`internal/archive/attributes.go`). Git for Windows enables
  `core.autocrlf` system-wide by default, so a clone of an archive checked
  documents out with CRLF and their hashes no longer matched.
- Two test fixtures used POSIX-only paths: the OpenCode GUI fixture's second
  project is now an absolute temporary path, and the macOS `/private` and
  `/tmp` cases of the automated-directory test run only off Windows.

### Documentation

- README, SPEC and PRD describe the GUI session directory and the
  `omp --session-dir <omp-home>/sessions-gui acp` launch it relies on.
- README and SPEC describe the archive's `.gitattributes`; README names Zed's
  Windows database path.

## Decisions and rationale

- OMP session headers do not record the client that created them, so GUI and
  CLI sessions are told apart by directory, not by content. The owner's Zed
  configuration launches `omp --session-dir ~/.omp/agent/sessions-gui acp`.
  Patching OMP to record the client was rejected: it would add a fork patch and
  make every export read session contents to classify them.
- The directory name is client-neutral, so another GUI can share it.
- Zed starts Claude Agent through `@agentclientprotocol/claude-agent-acp`
  (0.95.0 observed), whose SDK sets `CLAUDE_CODE_ENTRYPOINT=sdk-ts` unless the
  environment already sets one. Observed on 2026-10-24: a thread started in Zed
  wrote `entrypoint: "sdk-ts"` on every record, and Zed's `sidebar_threads`
  recorded its `session_id` under `agent_id = "claude-acp"`. `sdk-ts` alone
  cannot tell Zed from other SDK programs, so Zed's sidebar establishes
  membership, as Codex's sidebar database does for Codex. Setting a custom
  entrypoint through Zed's agent `env` was rejected: Claude Code branches on
  the entrypoint value (SDK mode, usage attribution, permissions).
- Document hashes stay over exact bytes. Normalizing line endings before
  hashing was rejected: it would weaken the integrity check every reader
  relies on. Telling Git not to convert keeps the bytes. An existing
  `.gitattributes` belongs to the owner and is never rewritten.
- Zed must be launched from the Dock or Spotlight. Launched from a
  Claude Desktop shell it inherits `CLAUDE_CODE_ENTRYPOINT=claude-desktop`,
  and its Claude Agent sessions would then pass as Desktop sessions.

## Compatibility and migration

- CLI: new optional `--omp-gui-session-dir` and `--zed-db`. Exports without
  `--gui-only` are unchanged.
- Archive: export adds a root `.gitattributes` (`* -text`) when none exists.
  No schema or document changes. An archive with its own `.gitattributes`
  that allows conversion (for example `* text=auto`) still gets CRLF on a
  Windows checkout; add `* -text` to it and check its files out again.
- GUI-only export now includes OMP when the OMP source is selected and the GUI
  directory has sessions, and Claude Agent sessions listed in Zed's sidebar.
  Users without that directory or Zed see no change.

## Known limitations and risks

- `go test -race` was not run on Windows: it needs cgo and a C compiler. CI
  runs it on Linux. The macOS suite was not rerun after the Windows changes.
- Git needs `core.longpaths` on Windows for archive paths longer than 260
  characters (seen when cloning under a deep temporary directory).
- The Session Manager UI does not expose the GUI directory or the Zed database;
  it always uses the defaults.
- Only Zed's stable channel database is read by default; Preview or Nightly
  builds need `--zed-db`.
- A Claude Desktop session imported into Zed and continued there gains
  `sdk-ts` records; it stays included only while Zed's sidebar lists it.
- Removing or archiving a Claude thread in Zed's sidebar drops it from later
  GUI-only exports.
