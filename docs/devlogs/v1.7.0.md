# Session Manager v1.7.0 Devlog

> Status: Development
> Date: 2026-10-24

## Objective and scope

GUI-only export also archives Oh My Pi conversations that the owner started in
a GUI client (Zed's Agent panel over ACP), while OMP runs from the CLI, which
are automation, stay out of it. Changing OMP itself, Claude sessions started
from Zed, and the Session Manager UI are outside this version.

## Work completed

### Export

- `Options.OMPGUISessionDir` and `export --omp-gui-session-dir` name the OMP
  session directory written by GUI clients; the default is
  `<omp-home>/sessions-gui` (`internal/archive/omp.go`, `internal/app/app.go`).
- GUI-only export no longer drops the OMP source. It reads only the GUI
  directory; a missing directory yields zero candidates, as before
  (`internal/archive/archive.go`).

### Documentation

- README, SPEC and PRD describe the GUI session directory and the
  `omp --session-dir <omp-home>/sessions-gui acp` launch it relies on.

## Decisions and rationale

- OMP session headers do not record the client that created them, so GUI and
  CLI sessions are told apart by directory, not by content. The owner's Zed
  configuration launches `omp --session-dir ~/.omp/agent/sessions-gui acp`.
  Patching OMP to record the client was rejected: it would add a fork patch and
  make every export read session contents to classify them.
- The directory name is client-neutral, so another GUI can share it.

## Compatibility and migration

- CLI: new optional `--omp-gui-session-dir`. Exports without `--gui-only` are
  unchanged.
- GUI-only export now includes OMP when the OMP source is selected and the GUI
  directory has sessions. Users without that directory see no change.

## Known limitations and risks

- The Session Manager UI does not expose the GUI directory; it always uses the
  default `<omp-home>/sessions-gui`.
- Claude sessions started from Zed (claude-agent-acp) are not yet classified as
  GUI-origin; their `entrypoint` value still needs to be observed.
